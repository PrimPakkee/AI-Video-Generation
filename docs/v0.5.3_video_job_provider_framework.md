# v0.5.3 Video Job / Provider / Asset 基础层

> 范围：v0.5.3
> 版本说明书：本文档描述 Video Mode 在 v0.5.3 中新增的 Job / Provider / Asset
> 基础层与 Video Mode 生成流程升级，与 [`docs/v0.5.2_video_mode_framework.md`](./v0.5.2_video_mode_framework.md)
> 与 [`docs/prompt_mode_freeze_spec.md`](./prompt_mode_freeze_spec.md) 配合阅读。
> 本版本**不接 Seedance**、**不接任何真实视频 API**、**不生成真实 mp4**、
> **不写远程视频链接**。

## 1. 版本定位

- v0.5.3 在 v0.5.2「Video Mode 独立框架」之上新增 **VideoJob 数据模型**、
  **Provider 抽象层** 与 **Asset endpoint**，并将 Video Mode 的生成流程从「单纯
  写历史记录」升级为「生成历史 + 创建 Mock VideoJob + 返回组合响应」。
- v0.5.3 **只**接入一个 `MockVideoProvider`，每次都返回
  `provider_not_configured` 形状的 shell 响应，**不调用任何远程服务**。
- v0.5.3 **不引入** Celery / Redis / RQ 等任务队列；VideoJob 仅作为「生成时
  同步写一次」的可见实体，不做真正的后台轮询调度。

## 2. 主要产品逻辑

- **首页右下角圆形按钮是唯一的生成入口**：
  - Prompt Mode 下显示 `Generate Prompt`；
  - Video Mode 下显示 `Generate Video`；
  - aria-label / `.send-tooltip` / 视觉文案随 `currentAppMode` 实时切换；
  - **不在 Video tab 内新增第二个「Generate Video」按钮**。
- **Video Mode 多阶段进度**：在 Video Mode 触发生成时，loading section 中替换
  spinner 为多阶段进度面板，依次推进 9 个阶段：Analyzing topic / Generating
  prompt / Writing script / Preparing provider / Submitting mock / Waiting /
  Saving / Done。最终阶段根据真实响应落到 `provider_not_configured` 或失败态。
- **结果页落点**：Video Mode 生成成功后，结果页默认进入 Video tab，并在
  Video tab 顶部展示 Video Job 状态面板（Status / Stage / Provider / Progress /
  Provider Job ID / Last Updated / Message）。
- **Prompt Mode 不变**：继续保持简单 spinner，所有 v0.4.10 既有逻辑保留。

## 3. VideoJob 数据模型

新增表 `video_jobs`（仅存在于 `data/video_history.db`，与 Prompt Mode 完全隔离）：

| 列 | 类型 | 说明 |
| ---- | ---- | ---- |
| `id` | int PK | 自增 |
| `history_id` | int, indexed | 关联 VideoHistory.id（无 DB 级 FK） |
| `provider` | str(50) | 当前仅 `'mock'` |
| `provider_job_id` | str(200) | 由 provider 返回，如 `mock_<uuid>` |
| `status` | str(50) | `pending` / `preparing` / `submitted` / `running` / `succeeded` / `failed` / `cancelled` / `provider_not_configured` |
| `stage` | str(80) | `analyzing_topic` / `generating_prompt` / `writing_script` / `preparing_provider_request` / `submitting_provider_job` / `generating_video` / `saving_assets` / `completed` / `provider_not_connected` / `failed` |
| `progress` | int | 0–100，advisory only |
| `request_json` / `response_json` | text | provider 请求/响应快照 |
| `error_message` | text | 失败时的人读消息 |
| `result_video_path` / `result_video_url` / `result_thumbnail_path` | str(500) | v0.5.3 永不写入真实路径 |
| `duration_seconds` | int | v0.5.3 不写 |
| `created_at` / `updated_at` / `submitted_at` / `completed_at` | datetime |  |
| `metadata_json` | text | 预留 |

`init_video_db()` 在启动时通过 `VideoBase.metadata.create_all` 创建该表。已有
`data/video_history.db` 在升级后会被自动新增 `video_jobs` 表，**不会**重建数据
库、**不会**删除任何旧数据。

`VideoJobRepository`（`web/db/video_job_repository.py`）提供：
- `create_job` / `get_job` / `get_latest_job_for_history` / `list_jobs_for_history` /
  `update_job_status` / `mark_cancelled`。

## 4. Provider 抽象层

新增包 `web/video_providers/`：

- `base.py` 中的 `VideoProvider` 是接口基类：
  - 类属性 `provider_name`；
  - 实例方法 `submit(request) / get_status(provider_job_id) / cancel(provider_job_id)`，
    抛 `NotImplementedError`；
  - 静态方法 `empty_response(provider, message)` 返回标准的
    `provider_not_configured` shell。
- `mock_provider.py` 中的 `MockVideoProvider` 是 v0.5.3 的唯一实现：
  - `provider_name = 'mock'`；
  - `submit` 返回 `{provider, provider_job_id, status: provider_not_configured,
    stage: provider_not_connected, progress: 85, message, video_url: None,
    video_path: None}`；
  - 不发出任何网络请求、不读任何 API key、不写任何文件。
- `__init__.py` 导出 `VideoProvider` 与 `MockVideoProvider`。

**严禁在 v0.5.3 内新增任何真实 provider 文件**（如 `seedance_provider.py`）。

## 5. API 变化

`web/app.py` 注册的新 endpoint：

| Method | Path | 说明 |
| ---- | ---- | ---- |
| POST | `/api/video/history/{history_id}/jobs` | 显式为已有记录创建 Mock VideoJob |
| GET | `/api/video/history/{history_id}/jobs/latest` | 取最新 VideoJob（可能为 null） |
| GET | `/api/video/jobs/{job_id}` | VideoJob 详情 |
| POST | `/api/video/jobs/{job_id}/refresh` | 刷新（v0.5.3 仅 mock，永远 `provider_not_configured`） |
| POST | `/api/video/jobs/{job_id}/cancel` | 标记为 `cancelled` |
| GET | `/api/video/history/{history_id}/asset/video` | 视频文件资源（v0.5.3 永远 404） |
| GET | `/api/video/history/{history_id}/asset/thumbnail` | 缩略图资源（v0.5.3 永远 404） |

升级的 endpoint：
- `POST /api/video/generate`：在 `create_history_record` 后立即调用
  `MockVideoProvider().submit(...)` 并写入 `video_jobs`，响应 JSON 中新增字段
  `video_job: {...}`（即 `VideoJob.to_dict()`）。
- `POST /api/video/history/{id}/regenerate`：同上，新版本也会自动创建 Mock
  VideoJob，并在响应中返回 `video_job`。
- `GET /api/video/history/{id}/download-all`：`metadata.json` 的
  `export_schema_version` 由 `video_v0.5.1` 修正为 `video_v0.5.3`；其余只读
  契约**完全不变**（仍为 `raw_text.txt / preview.txt / overview.txt /
  web_copy.txt / metadata.json`，不含 mp4 / mov / 视频 URL / token / API key、
  对数据库零写入）。

## 6. Asset endpoint 安全约束

`/api/video/history/{id}/asset/{video|thumbnail}` 通过
`_resolve_safe_outputs_path()` 实施：

1. 候选路径若为相对路径，先解析到 `project_root/outputs/` 之下；
2. 调用 `Path.resolve()` 后用 `relative_to(outputs_root)` 校验，**任何指向
   `outputs/` 之外的路径都被拒绝**；
3. 文件不存在或非普通文件 → 404；
4. 永远不暴露绝对文件系统路径给前端。

v0.5.3 内 VideoHistory.video_file_path / VideoJob.result_video_path 始终为
NULL，所以 asset endpoint 在正常使用下**始终返回 404**。

## 7. 前端集成

- 新增 `updateGenerateButtonForCurrentMode()`：在 `applyModeChrome` 与
  `switchAppMode` 中调用，更新首页圆形按钮的 aria-label 与 `.send-tooltip`。
- 新增 `VIDEO_GENERATION_STEPS` 与五个进度函数
  (`startVideoGenerationProgress` / `advanceVideoGenerationProgress` /
  `completeVideoGenerationProgress` / `failVideoGenerationProgress` /
  `resetVideoGenerationProgress`)：仅在 Video Mode 下接管 loading panel。
- 新增 `currentVideoJob` 全局状态 + `renderVideoJobStatus(job)`：在 Video tab
  顶部展示 Status / Stage / Provider / Progress / Provider Job ID / Last
  Updated / Message。
- `renderHistoryRecord(item)` 在 Video Mode 下额外发起
  `/api/video/history/{id}/jobs/latest` 请求，得到的 job 写入
  `currentVideoJob` 并 `renderVideoJobStatus`。
- 视频播放器 `<video>` 元素的 src 通过 `applyVideoAssetSrc()` 路由到
  `/api/video/history/{id}/asset/video`，**永不**赋绝对文件系统路径。v0.5.3
  下因为没有真实资源，函数会清空 src。

## 8. AI Review tab 文案修正

专属文案被替换为：

> evaluate generated video assets independently from Prompt Mode.

Video Mode 下**仍然不调用** Prompt Mode `/api/history/{id}/review`。

## 9. Prompt Mode 保护边界

Prompt Mode v0.4.10 全部保护**继续生效**（详见
[`docs/prompt_mode_freeze_spec.md`](./prompt_mode_freeze_spec.md)）：

- 不修改 Prompt 生成主提示词；
- 不修改 AI Review 评分标准 / schema；
- 不修改 NotebookLM Prompt 输出结构；
- 不修改 Prompt Mode Download All 只读契约；
- 不修改 `prompt_history` / `prompt_reviews` schema；
- 不修改 Prompt Mode Raw Text / Regenerate / 版本管理 / 收藏 / 置顶 / 回收站。

v0.5.3 **不跨库写入**：所有 VideoJob 写入只走 `get_video_db()` /
`VideoSessionLocal`，从不接触 Prompt Mode 表。
