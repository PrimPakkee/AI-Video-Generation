# v0.6.4 — gpt-image-2 接入

## 概要

v0.6.4 把 Image Video 路线从「本地 Pillow 几何图」升级成「**gpt-image-2 真实图像生成 + 本地 Pillow 文字叠加**」。每张 slide 的英文 `image_prompt`（v0.6.3 已经由 LLM 写好并存进 Raw Text）现在会真的发送到公司 OpenAI-compatible 网关的 `images/generations` endpoint，拿到的 PNG 用作底图，title / caption / badge / 进度脚标仍由本地 Pillow 在底图上叠加 —— 防止图像模型自己写字时出现拼写/字体/布局乱码。

## 不做的事（继续保留 v0.6.3 边界）

- 不调 Seedance、不调 APX video、不调 TTS、不做字幕 burn-in
- 不修改 `.env`（操作员自己加 `APX_IMAGE2_*`）
- 不 git add / commit / push
- 默认 smoke 仍然纯本地（`IMAGE_VIDEO_DISABLE_LLM=1` + `IMAGE_VIDEO_DISABLE_IMAGE2=1`）

## API 接入信息（已经实测通过）

```
POST http://ai-service.tal.com/openai-compatible/v1/images/generations
Headers:
  api-key: <appId:apiKey>          # 整串原样塞进去
  Content-Type: application/json
Body:
  {"model": "gpt-image-2", "prompt": "...", "size": "1792x1024", "quality": "high"}

Response:
  {"data": [{"b64_json": "<png base64>"}], "size": "...", "quality": "...", ...}
```

测试结论：
- `size=1792x1024` ✅（接近 16:9，比默认 1254×1254 省一次裁切）
- `quality=high` ✅（output_tokens 从 229 → 8232，画质质变）
- 单次延迟 30–60s → **必须并发**

## 环境变量

操作员需要在 `.env` 里加：

```
APX_IMAGE2_ENABLED=true
APX_IMAGE2_API_KEY=<整串 appId:apiKey>
APX_IMAGE2_BASE_URL=http://ai-service.tal.com/openai-compatible/v1   # 可选，有默认
APX_IMAGE2_MODEL=gpt-image-2                                          # 可选
APX_IMAGE2_SIZE=1792x1024                                             # 可选
APX_IMAGE2_QUALITY=high                                               # 可选
APX_IMAGE2_TIMEOUT=180                                                # 可选
APX_IMAGE2_CONCURRENCY=4                                              # 可选
```

`APX_IMAGE2_API_KEY` 永不入库、永不写到任何 `outputs/` 文件、永不返回前端，只通过 HTTP header 送给网关。

## 新增文件

- `web/image_providers/__init__.py`
- `web/image_providers/base.py` — `ImageProvider` 抽象接口 + `RenderedImage` dataclass + `ImageProviderError`。**本身不 import requests**。
- `web/image_providers/apx_image2_provider.py` — **v0.6.4 中唯一允许真发网络的文件**。`requests` 在 `generate()` 内 lazy import，从 base64 decode 出 PNG bytes，header 探测 PNG 的真实 width/height（不信网关返回的 size 字段）。

## 改动文件

- `web/image_video_pipeline.py`
  - `_generate_image2_backgrounds(slide_plan, image_video_dir, progress_cb)`：用 `ThreadPoolExecutor` 并发调用 image2，单张失败不阻塞其他张。每张返回的 PNG 持久化到 `outputs/<slug>/image_video/image2_backgrounds/slide_NN_image2.png`，全量 debug 写到 `image2_debug.json`。
  - `_resize_to_canvas`：把 image2 PNG（1792×1024 或别的）按比例放大到 1920×1080 的 16:9 画布，差异部分中心裁切。
  - `_draw_text_band_over_background`：在 image2 底图上加一条半透明白带，再叠 title/caption。
  - `_render_slide(..., background=Image|None)`：有 background 时走新 path（image2 模式），没有时仍走原 v0.6.3 几何图 path（fallback）。
  - 失败 fallback 是 **per-slide 粒度** 的：第 N 张图 image2 失败 → 第 N 张回退到 Pillow，**整段视频不崩**。
  - `IMAGE_VIDEO_DISABLE_IMAGE2=1` 短路（smoke / 离线复现用）。

- `web/app.py`
  - `IMAGE_VIDEO_RUN_STAGES` 从 6 个升到 **7 个**（新增 `generate_slide_images`，把原 `render_slide_images` 改名 `render_slide_overlays`）。
  - `_build_image_video_metadata_json` / `_build_image_video_response_payload` 透传：
    - `image2_called`、`image2_succeeded`、`image2_failed`、`image2_requested`
    - `image2_disabled_by_env`、`image2_skipped_reason`
    - `image_sources[]`（每张 slide 的来源："image2" 或 "pillow_fallback"）
    - `media_api_called`、`network_call_performed` 现在会因 image2 真发而翻 true（之前只反映 LLM）

- `web/static/index.html`
  - Generation Evidence 面板新增 **Image2 success / total** 行
- `web/static/main.js`
  - `renderGenerationEvidencePanel` 填 `image2_ratio` 和新的 `media_api_called`

## Stage 列表（v0.6.4）

| # | Stage key | 说明 | 真实耗时来源 |
|---|---|---|---|
| 1 | `validate_topic` | 检查 title 非空 | worker |
| 2 | `plan_slides` | resolve_slide_count + 角色分配 | pipeline |
| 3 | `write_slide_content` | gpt-5-chat 写文案 + 中文 overview | pipeline (LLM 调用) |
| 4 | `generate_slide_images` | **gpt-image-2 并发拉图**（v0.6.4 新增） | pipeline (image2 调用) |
| 5 | `render_slide_overlays` | Pillow 在底图上叠 title/caption/badge | pipeline |
| 6 | `compose_final_video` | FFmpeg concat → mp4 | pipeline |
| 7 | `save_history` | 写 VideoHistory + metadata | worker |

## Failure modes

| 情况 | 行为 |
|---|---|
| `APX_IMAGE2_ENABLED` 未开 | stage 4 显示 "Skipped — APX_IMAGE2_* not configured; Pillow only."，所有 slide 走 Pillow 几何图 fallback |
| `IMAGE_VIDEO_DISABLE_IMAGE2=1` | stage 4 显示 "Skipped — IMAGE_VIDEO_DISABLE_IMAGE2 set"，全 Pillow |
| 单张 image2 HTTP 错误 / 超时 | 那一张回退到 Pillow，evidence 中 `image2_failed += 1` |
| 单张 PNG 解码失败 | 同上，那一张回退 Pillow |
| `requests` 未安装 | 整段 stage 4 跳过，全 Pillow，不崩 |
| FFmpeg 缺失 | 不变 — v0.6.3.1 的诊断行为继续生效 |

## 自测命令

```bash
# 默认 smoke（offline，零网络）
python3 scripts/smoke_image_video_pipeline.py

python3 scripts/smoke_image_video_pipeline.py --with-llm --with-image2

python3 scripts/run_stability_checks.py
```

## 浏览器验证清单

1. 重启 uvicorn（让进程读到新加的 `APX_IMAGE2_*`）
2. 切到 Video Mode → Image Video → 输入题目 → Generate
3. 进度面板应该出现**第 4 个新阶段**「Generate slide images (gpt-image-2)」，真实耗时几十秒到几分钟（取决于 slide_count 和并发）
4. Generation Evidence 面板应该显示：
   - `Media API call: Yes`
   - `Image2 called: Yes`
   - `Image2 success / total: N / N`
5. 视频 tab 播放出来的画面背景应该是真实图像（不再是几何图），文字仍由 Pillow 干净叠加
