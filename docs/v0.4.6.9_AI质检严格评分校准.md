## 问题背景

在 v0.4.6.8 完成手动触发重构后,AI Review 功能已经可以稳定生成和展示,交互逻辑清晰。但**评分质量**存在严重问题,导致质检功能缺乏实际区分度:

### 症状 1: 分数普遍过高,集中在 94-100 分

- 大部分 prompt 都能获得 94-100 分
- 几乎所有 prompt 都在"优秀"区间
- **无法区分高质量 prompt 和普通 prompt**
- 用户难以从分数中获得改进方向

**示例**:
- 一个结构完整但内容泛泛的 prompt: 96 分
- 一个精心设计、内容具体的 prompt: 98 分
- **只有 2 分差距,区分度太低**

---

### 症状 2: 即使 prompt 明显存在问题,仍然给出 90+ 高分

**示例 1: 标题残缺**
```markdown
## Title
Wh

## Topic
Interesting mathematical puzzle about probability
...
```
- 标题只有 "Wh" 两个字母,明显不完整
- AI Review 给出: **92 分**
- Completeness: 14/15
- **问题**: 即使存在明显缺陷,分数仍然很高

**示例 2: 缺少答案**
```markdown
## Question
Which door should you choose to maximize your chance of winning?

## Reasoning Steps
1. There are two doors
2. One has a prize
3. Equal probability means either choice is valid
```
- 有问题(Question)但没有答案(Correct Answer)
- 逻辑推理步骤存在但没有明确结论
- AI Review 给出: **89 分**
- Logical Correctness: 17/20
- **问题**: 逻辑不完整,但分数仍然很高

**示例 3: 内容泛泛**
```markdown
## Title
Educational Math Video

## Topic
Math concept explanation

## Core Concept
Educational content

## Puzzle Setup
There is a problem to solve.
```
- 所有内容都是模板化、泛泛而谈
- 没有任何具体的主题、问题或解决方案
- AI Review 给出: **94 分**
- Educational Clarity: 9/10
- **问题**: 完全通用模板,但分数仍然极高

---

### 症状 3: LLM Comment 里明明写了问题,但分数没有同步下降

**示例**:

| Criterion | Score | LLM Comment |
|-----------|-------|-------------|
| Completeness | 14/15 | "The prompt is strong. **However**, the title is missing some details." |
| Logical Correctness | 19/20 | "Logic is good **but** the reasoning is **somewhat unclear**." |
| Visual Directability | 10/10 | "Visual plan is **missing concrete scene details**." |
| Educational Clarity | 10/10 | "Clear explanation. **Minor gap** in examples." |

**问题分析**:
- ✅ LLM 正确识别了问题:missing / unclear / minor gap
- ❌ 但分数没有相应下降:10/10, 14/15, 19/20
- ❌ **评论和分数不一致**,用户看到评论里有问题,但分数仍然是满分或接近满分

**根本矛盾**:
- 如果评论里写了 "However / missing / unclear / but",说明存在问题
- 如果存在问题,分数应该显著下降(至少 15-25%)
- **当前系统没有强制这种一致性**

---

### 症状 4: 评论缺乏个性化,难以提供具体改进方向

**示例评论**:
- "The prompt is well-structured."
- "Good visual plan."
- "Clear explanation."
- "Mostly complete."

**问题**:
- ✅ 评论是正面的
- ❌ 但评论没有引用具体内容
- ❌ 没有指出具体优点在哪里
- ❌ 没有指出具体问题在哪里
- ❌ **用户无法从评论中得到可操作的改进建议**

**期望评论格式**:
```
Evidence: [引用 prompt 中的具体内容]
Weakness: [如果有问题,明确指出是什么问题]
Improvement: [如果需要改进,给出具体建议]
```

## 根本原因分析

### 原因 1: 原评分尺度过宽,缺乏梯度

**原尺度**:
- 90-100: Excellent
- 80-89: Good
- 70-79: Acceptable
- <70: Needs work

**问题**:
- "Excellent" 区间占 10 分(90-100),范围过大
- "Good" 区间占 10 分(80-89),范围过大
- LLM 倾向于给高分,大部分 prompt 都在 90+
- **缺乏细粒度区分**

---

### 原因 2: 缺少 Hard Cap(硬性上限)

**当前行为**:
- 即使 prompt 存在明显缺陷,LLM 仍然可能给出高分
- 例如:标题只有 "Wh" 两个字母,但 Completeness 仍然能得到 14/15

**问题**:
- **没有强制规则**限制存在严重缺陷的 prompt 分数上限
- LLM 只要看到其他部分完整,就会给高分
- **缺少"一票否决"机制**

**期望行为**:
- 如果标题缺失或过短 → 总分上限 72
- 如果没有答案(Correct Answer) → 总分上限 65
- 如果内容过于泛泛 → 总分上限 82
- **通过程序化规则强制执行上限**

---

### 原因 3: LLM 只要看到结构完整,就容易给高分

**LLM 倾向**:
- LLM 看到 prompt 包含所有必需的 section(Title / Topic / Question / Answer / Visual Style 等)
- 即使内容是泛泛模板,LLM 也会认为"结构完整"
- **LLM 倾向于奖励结构,而非内容质量**

**问题**:
- 结构完整 ≠ 内容高质量
- 模板化内容应该得到较低分数
- **需要明确引导 LLM 关注内容质量,而非结构**

---

### 原因 4: 评论中出现问题,但分数没有同步下降

**当前行为**:
- LLM 在评论中写:"However, the title is missing some details."
- 但分数仍然是 14/15(93%)

**问题**:
- **LLM 识别了问题,但没有相应降低分数**
- 这可能是因为:
  - LLM 先生成评论,再生成分数
  - 生成分数时没有强制参考评论
  - 或者 LLM 认为"minor issue"不值得大幅扣分

**期望行为**:
- 如果评论中包含负面词汇(however / missing / unclear / incomplete 等)
- 分数应该相应下降 15-25%
- **需要后处理校准,确保分数和评论一致**

---

### 原因 5: 没有强制个性化证据和具体扣分理由

**当前 prompt 设计**:
- 没有要求 LLM 引用 prompt 中的具体内容
- 没有要求 LLM 明确指出问题所在
- 没有要求 LLM 给出具体改进建议

**问题**:
- LLM 倾向于生成通用评论
- **用户无法从评论中得到可操作的反馈**

**期望行为**:
- 强制要求评论格式:Evidence / Weakness / Improvement
- Evidence: 必须引用 prompt 中的具体内容
- Weakness: 如果有问题,必须明确指出
- Improvement: 如果需要改进,必须给出具体建议

---

### 原因 6: 缺少本地后处理校准

**当前架构**:
- LLM 生成评分 → 直接存入数据库 → 展示给用户
- **没有本地校准逻辑**

**问题**:
- 完全依赖 LLM 的判断
- LLM 可能不稳定(有时严格,有时宽松)
- **缺少程序化保障**

**期望架构**:
```
LLM 生成评分
  ↓
本地质量检测(quality flags)
  ↓
应用硬性上限(hard caps)
  ↓
校准分数-评论一致性(consistency calibration)
  ↓
存入数据库
```

## 设计目标

将 AI Review 从**宽松评分**改为**严格、可区分、可解释、可校准**的质检系统。

### 核心原则

✅ **严格评分**:只有真正高质量的 prompt 才能获得 95+ 高分  
✅ **明显缺陷必须反映在分数上**:标题残缺、缺答案、内容泛泛等问题必须显著降低分数  
✅ **分数-评论一致性**:如果评论中提到问题,分数必须相应下降  
✅ **个性化评价**:评论必须引用具体内容,指出具体问题,给出具体建议  
✅ **程序化保障**:通过本地校准逻辑,确保评分质量不完全依赖 LLM

#### 2. 重写严格评分尺度

**旧尺度**(过宽):
```
90-100: Excellent
80-89: Good
70-79: Acceptable
<70: Needs work
```

**新尺度**(严格):
```
95-100: Exceptional (RARE - only for prompts with topic-specific detail, complete logic, zero ambiguity)
88-94: Very strong (clear, complete, minimal issues)
78-87: Good / usable (solid structure, some generic content or minor gaps)
65-77: Needs revision (missing key sections, logic gaps, or overly generic)
50-64: Weak (multiple major issues)
<50: Poor (fundamentally incomplete or broken)
```

**关键改进**:
- ✅ 95-100 标记为 RARE,只有顶级 prompt 才能达到
- ✅ 增加细粒度区间(95-100 / 88-94 / 78-87 / 65-77 / 50-64 / <50)
- ✅ 每个区间都有明确定义

#### 3. 新增质量检测函数: analyze_prompt_quality_flags()

**功能**:
- 在调用 LLM 之前,先用程序化规则检测 prompt 是否存在明显缺陷
- 返回 10 种质量 flag

**检测项**:
1. `title_missing_or_too_short`: 标题缺失或过短(<8 字符,或只有 "Wh" / "Test" 等)
2. `topic_missing_or_too_short`: 主题缺失或过短(<15 字符)
3. `no_clear_question`: 没有明确的问题(Question section)
4. `no_correct_answer`: 没有明确的答案(Correct Answer section)
5. `no_reasoning_steps`: 没有推理步骤(Reasoning Steps section)
6. `no_visual_plan`: 没有视觉计划(Visual Style / Visual Direction section)
7. `no_single_narrator_constraint`: 没有明确禁止对话格式的约束
8. `too_generic`: 内容过于泛泛(标题/主题/核心概念都是通用词汇)
9. `suspiciously_short_prompt`: prompt 总长度过短(<500 字符)
10. `incomplete_sections`: 多个关键 section 缺失(>=3 个)

**实现位置**:
- `scripts/llm_topic_enhancer.py`
- 在 `review_prompt()` 调用 LLM 之前执行

#### 4. 新增硬性上限函数: apply_strict_score_caps()

**功能**:
- 基于 quality flags,强制限制总分和单项分数上限
- **一票否决机制**:存在严重缺陷的 prompt,无论 LLM 给多高分数,总分都会被强制降低

**规则**:

| Quality Flag | Individual Dimension Caps | Total Score Cap |
|--------------|---------------------------|-----------------|
| `title_missing_or_too_short` | Completeness ≤ 9/15 | ≤ 72 |
| `no_correct_answer` | Logical Correctness ≤ 12/20 | ≤ 65 |
| `no_clear_question` | Logical Correctness ≤ 10/20 | ≤ 68 |
| `no_reasoning_steps` | Logical Correctness ≤ 14/20 | ≤ 75 |
| `no_visual_plan` | Visual Directability ≤ 6/10 | ≤ 80 |
| `too_generic` | Educational Clarity ≤ 7/10 | ≤ 82 |
| `suspiciously_short_prompt` | Completeness ≤ 10/15 | ≤ 70 |
| `incomplete_sections` | Completeness ≤ 8/15 | ≤ 65 |

**工作流程**:
```python
# 1. LLM 生成初始评分
review_data = self._build_review_table_from_llm_scores(llm_data)

# 2. 检测质量 flags
quality_flags = self.analyze_prompt_quality_flags(raw_prompt)

# 3. 应用硬性上限
review_data = self.apply_strict_score_caps(review_data, quality_flags)
```

**效果**:
- 标题残缺的 prompt:无论 LLM 给多高分,总分最多 72
- 缺答案的 prompt:无论 LLM 给多高分,总分最多 65
- 泛泛模板的 prompt:无论 LLM 给多高分,总分最多 82

---

#### 5. 新增一致性校准函数: calibrate_score_comment_consistency()

**功能**:
- 检测评论中是否包含负面词汇(however / missing / unclear 等)
- 如果评论中提到问题,但分数过高,强制降低分数
- 确保**分数和评论一致**

**负面词汇列表**:

**Mild**(轻微问题):
- however, minor gap, could improve, lacks some, somewhat, slightly, a bit

**Severe**(严重问题):
- missing, unclear, incomplete, vague, generic, too short, confusing, ambiguous, weak

**校准规则**:
- 如果评论包含 **Severe 词汇** 且分数 ≥ 90%:
  - 降低到 70%(例如 14/15 → 10/15)
  - 添加说明:"Score calibrated downward because the review comment identified a concrete weakness."

- 如果评论包含 **Mild 词汇** 且分数 ≥ 95%:
  - 降低到 85%(例如 15/15 → 13/15)
  - 添加说明:"Score calibrated downward to reflect the minor issue mentioned in the comment."

**工作流程**:
```python
# 3. 应用硬性上限
review_data = self.apply_strict_score_caps(review_data, quality_flags)

# 4. 校准一致性
review_data = self.calibrate_score_comment_consistency(review_data)
```

#### 7. 重写 User Prompt:增加维度级别的严格指导

**为每个维度增加具体评分指导**:

**示例: Completeness (15%)**
```
Completeness (max 15):
- 15/15: All key sections exist AND are topic-specific with concrete details
- 12-14/15: All sections exist but some are generic or brief
- 9-11/15: Missing 1-2 minor sections OR multiple sections are too generic
- 6-8/15: Missing major sections (e.g., no answer, no reasoning, no visual plan)
- <6/15: Multiple critical sections missing
```

**示例: Logical Correctness (20%)**
```
Logical Correctness (max 20):
- 20/20: ONLY if the logic is airtight, the answer is explicitly stated, and all reasoning steps are clear
- 16-19/20: Logic is sound but minor gaps or ambiguities exist
- 12-15/20: Logic is present but unclear, or answer is vague, or reasoning is incomplete
- 8-11/20: Logic has errors, or answer is missing, or reasoning is broken
- <8/20: Fundamental logical flaws or no clear reasoning
```

**强制评论格式**:
```
Your comment MUST follow this structure:
Evidence: [Quote or reference specific content from the prompt]
Weakness: [If any, state the concrete problem]
Improvement: [If needed, give specific actionable advice]

CRITICAL: If you identify a weakness in the comment, the score MUST reflect that.
Do NOT write "However, the title is missing details" and still give 14/15.
If there is a weakness, reduce the score by at least 15-25%.
```

#### 8. 集成三层校准流程

**完整流程**:
```python
def review_prompt(self, raw_prompt: str, ...) -> dict:
    # 1. 调用 LLM 生成初始评分
    llm_data = self._call_llm_for_review(raw_prompt)
    
    # 2. 解析并规范化 LLM 输出
    review_data = self._build_review_table_from_llm_scores(llm_data)
    
    # 3. 质量检测(Quality Flags)
    quality_flags = self.analyze_prompt_quality_flags(raw_prompt)
    
    # 4. 应用硬性上限(Hard Caps)
    review_data = self.apply_strict_score_caps(review_data, quality_flags)
    
    # 5. 校准一致性(Consistency Calibration)
    review_data = self.calibrate_score_comment_consistency(review_data)
    
    # 6. 返回最终结果
    return review_data
```

**三层保障**:
- **Layer 1 - Quality Flags**: 程序化检测明显缺陷
- **Layer 2 - Hard Caps**: 强制执行分数上限
- **Layer 3 - Consistency Calibration**: 确保分数和评论一致

### 修复 2: 新增质量检测函数

**文件**: `scripts/llm_topic_enhancer.py`

**位置**: 在 `_normalize_review_data()` 之后, `_build_review_table_from_llm_scores()` 之前

**新增函数**:
```python
def analyze_prompt_quality_flags(self, raw_prompt: str) -> dict:
    """
    Analyze prompt for quality issues and return flags.
    Used to apply strict score caps and ensure broken prompts get appropriately low scores.
    """
    flags = {}
    
    # Extract sections
    sections = {}
    current_section = None
    for line in raw_prompt.split('\n'):
        if line.strip().startswith('##'):
            current_section = line.strip()[2:].strip().lower()
            sections[current_section] = []
        elif current_section:
            sections[current_section].append(line.strip())
    
    # 1. title_missing_or_too_short
    title_content = ' '.join(sections.get('title', [])).strip()
    flags["title_missing_or_too_short"] = (
        len(title_content) < 8 or
        title_content.lower() in ["wh", "why", "test", "untitled", "title", ""]
    )
    
    # 2. topic_missing_or_too_short
    topic_content = ' '.join(sections.get('topic', [])).strip()
    flags["topic_missing_or_too_short"] = len(topic_content) < 15
    
    # 3. no_clear_question
    question_content = ' '.join(sections.get('question', [])).strip()
    flags["no_clear_question"] = len(question_content) < 10
    
    # 4. no_correct_answer
    answer_content = ' '.join(sections.get('correct answer', [])).strip()
    flags["no_correct_answer"] = len(answer_content) < 10
    
    # 5. no_reasoning_steps
    reasoning_content = ' '.join(sections.get('reasoning steps', [])).strip()
    flags["no_reasoning_steps"] = len(reasoning_content) < 20
    
    # 6. no_visual_plan
    visual_style = ' '.join(sections.get('visual style', [])).strip()
    visual_direction = ' '.join(sections.get('visual direction', [])).strip()
    flags["no_visual_plan"] = (len(visual_style) < 15 and len(visual_direction) < 15)
    
    # 7. no_single_narrator_constraint
    format_req = ' '.join(sections.get('format requirements', [])).strip().lower()
    constraints = ' '.join(sections.get('constraints', [])).strip().lower()
    flags["no_single_narrator_constraint"] = (
        'single narrator' not in format_req and
        'no dialogue' not in format_req and
        'monologue' not in format_req and
        'single narrator' not in constraints
    )
    
    # 8. too_generic
    generic_phrases = [
        "educational content", "math concept", "general viewers",
        "short format", "there is a problem", "the solution is provided",
        "clean background", "clear narration", "accurate content"
    ]
    prompt_lower = raw_prompt.lower()
    generic_count = sum(1 for phrase in generic_phrases if phrase in prompt_lower)
    flags["too_generic"] = generic_count >= 5
    
    # 9. suspiciously_short_prompt
    flags["suspiciously_short_prompt"] = len(raw_prompt.strip()) < 500
    
    # 10. incomplete_sections
    required_sections = [
        'title', 'topic', 'question', 'correct answer',
        'reasoning steps', 'visual style'
    ]
    missing_count = sum(1 for sec in required_sections if sec not in sections or len(' '.join(sections[sec]).strip()) < 10)
    flags["incomplete_sections"] = missing_count >= 3
    
    return flags
```

```python
def apply_strict_score_caps(self, review_data: dict, quality_flags: dict) -> dict:
    """
    Apply hard caps based on detected quality flags.
    Ensures broken prompts cannot receive high scores even if LLM is generous.
    """
    if not quality_flags:
        return review_data

        # Answer issues

        if quality_flags.get("no_reasoning_steps"):

        # Short prompt
        if quality_flags.get("suspiciously_short_prompt"):
            if criterion == "Completeness" and score > 10:
                row["score"] = 10

        # Incomplete sections
        if quality_flags.get("incomplete_sections"):
            if criterion == "Completeness" and score > 8:
                row["score"] = 8
                row["llm_comment"] += " [Strict cap applied: multiple critical sections are missing.]"
    
    # Recalculate total score
    new_total = sum(row.get("score", 0) for row in rows)
    
    # Total score caps
    if quality_flags.get("title_missing_or_too_short") and new_total > 72:

        new_total = 70
    if quality_flags.get("incomplete_sections") and new_total > 65:
        new_total = 65
    
    review_data["total_score"] = new_total
    
    return review_data
```

```python
def calibrate_score_comment_consistency(self, review_data: dict) -> dict:
    """
    Calibrate scores when comments mention weaknesses but scores are still high.
    Ensures score-comment consistency.
    """
    rows = review_data.get("rows", [])
    
    negative_words_mild = [
        "however", "minor gap", "could improve", "lacks some",
        "somewhat", "slightly", "a bit"
    ]
    negative_words_severe = [
        "missing", "unclear", "incomplete", "vague", "generic",
        "too short", "confusing", "ambiguous", "weak"
    ]
    
    for row in rows:
        criterion = row.get("criterion", "")
        max_score = row.get("max_score", 10)
        score = row.get("score", 0)
        comment = row.get("llm_comment", "").lower()
        
        # Check for negative words
        has_mild_negative = any(word in comment for word in negative_words_mild)
        has_severe_negative = any(word in comment for word in negative_words_severe)
        
        score_ratio = score / max_score if max_score > 0 else 0
        
        # Severe issue but high score (>= 90%)
        if has_severe_negative and score_ratio >= 0.9:
            new_score = int(max_score * 0.70)  # Reduce to 70%
            if new_score < score:
                row["score"] = new_score
                row["llm_comment"] += f" [Score calibrated downward from {score}/{max_score} to {new_score}/{max_score} because the review comment identified a concrete weakness.]"
        
        # Mild issue but near-perfect score (>= 95%)
        elif has_mild_negative and score_ratio >= 0.95:
            new_score = int(max_score * 0.85)  # Reduce to 85%
            if new_score < score:
                row["score"] = new_score
                row["llm_comment"] += f" [Score calibrated downward from {score}/{max_score} to {new_score}/{max_score} to reflect the minor issue mentioned in the comment.]"
    
    # Recalculate total score
    new_total = sum(row.get("score", 0) for row in rows)
    review_data["total_score"] = new_total
    
    return review_data
```

**关键逻辑**:
- ✅ 检测评论中的负面词汇
- ✅ 区分 Mild 和 Severe 问题
- ✅ 如果分数过高,强制降低
- ✅ 添加校准说明

## 已知限制

1. **校准逻辑依赖关键词检测**
   - `calibrate_score_comment_consistency()` 依赖负面词汇列表
   - 如果 LLM 用其他词汇表达问题,可能无法检测到
   - **未来改进**: 使用语义分析而非关键词匹配

2. **Hard caps 基于程序化规则,可能过于刚性**
   - 例如:如果标题虽然短,但非常精准,仍然会被限制
   - **未来改进**: 结合 LLM 判断和程序化规则

3. **LLM 可能仍然偶尔给出宽松评分**
   - 即使有严格 prompt,LLM 可能仍然不稳定
   - **缓解措施**: 三层校准逻辑提供兜底保障

4. **评论格式强制可能不够完美**
   - User prompt 要求 Evidence / Weakness / Improvement 格式
   - 但 LLM 可能不严格遵守
   - **缓解措施**: 如果格式不符合,至少内容更加具体

---

## 未来改进方向

1. **多轮评审**
   - 第一轮:LLM 生成初始评分
   - 第二轮:LLM 自我审查,检查分数-评论一致性
   - 第三轮:本地校准

2. **评分历史和趋势**
   - 记录每个 prompt 的历次评分
   - 展示评分趋势图
   - 帮助用户了解 prompt 优化历程

3. **批量重新评分**
   - 当评分标准更新后,批量重新评分所有 prompt
   - 生成评分变化报告

4. **评分标准可配置**
   - 允许用户自定义评分尺度
   - 允许用户自定义 hard cap 规则
   - 适应不同用户的质量标准
