# v0.6.2 — Seedance Prompt Quality Gate + English Compiler + Real Progress Fix

## 1. Why this release exists

v0.6.0 wired the real APX Seedance provider; v0.6.1 forced English-only
16:9 landscape output. By the time the first real videos came back from
APX, the actual `submit_payload.prompt` showed the failure mode that
motivates v0.6.2:

```
Subject (English): this topic
Core concept: this topic
Narration body: A
Step-by-step reasoning: AB / BAB
Scene visual: A / B
Allowed on-screen text: this topic / Question / Answer / Why?
```

The transport worked. The prompt did not. v0.6.2 keeps the v0.6.1 surface
and only fixes:

1. The compiler input — strictly normalise every field before building the
   prompt; never fabricate `this topic` / `A` / `AB` / `BAB`.
2. The compiler output — emit a compact, video-model-friendly English
   prompt with positive narrator instructions; remove the "does not yet
   generate audio" wording.
3. A hard quality gate that runs **immediately before** every real APX
   submit. If the gate fails, no APX call is made; a `blocked_prompt_quality`
   `VideoJob` is recorded and surfaced on the UI.
4. A real per-stage run store on the homepage — no more `setInterval`
   advancing through fabricated stages on a 1.5 s timer.
5. A Provider Evidence Summary panel so future debugging never has to
   guess whether APX was called.

## 3. Compiler input normalisation

The compiler now runs every upstream asset bundle through
`normalize_seedance_prompt_input(...)` before building the final prompt.
The function returns a clean structured view:

```python
{
  "original_topic": "...",
  "english_subject": "...",
  "english_title": "...",
  "english_question": "...",
  "video_goal": "...",
  "core_concept": "...",
  "correct_answer": "...",
  "hook_line": "...",
  "narration_script": "...",
  "ending_line": "...",
  "scene_plan": [...],
  "allowed_on_screen_text": [...],
  "duration_seconds": 15,
  "aspect_ratio": "16:9",
  "resolution": "1920x1080",
  "style": "clean whiteboard infographic educational explainer",
  "prompt_quality_failed": false,
  "quality_block_reasons": [],
  "needs_human_review": false,
}
```

Hard rules:

- No field falls back to `this topic`. Empty stays empty and gets a block
  reason.
- No field falls back to `A` / `B` / `AB` / `BA` / `BAB` / `ABA`. Those
  strings are detected via `BANNED_STANDALONE_TOKENS` and treated as empty.
- `correct_answer`, `narration_script`, `core_concept`, `scene_plan` and
  `allowed_on_screen_text` each emit a specific block reason when missing.
- `allowed_on_screen_text` must have ≥ 2 entries and must not be entirely
  generic (`Question` / `Answer` / `Why?`).
- All CJK characters are stripped.

## 4. Final Seedance prompt format

`build_seedance_prompt(normalized)` emits a compact, sectioned English
prompt (no NotebookLM-style headers, no debugging chatter):

```
Task:
Create a 15-second 16:9 landscape educational explainer video about: "..."

Format:
16:9 landscape, 1920x1080, ..., white background, simple line art, large
readable English text only.

Voiceover:
Use one clear English narrator voiceover. Single narrator monologue only.
No dialogue, no interview, no podcast, no two speakers.

Core explanation:
Core concept: ...
Correct answer (must be shown correctly): ...
Hook: ...
Narration body: ...
Closing: ...

Scene plan:
Scene 1 (0-5s): visual: ...; narration: ...; on-screen text: ...
Scene 2 (5-10s): visual: ...; narration: ...; on-screen text: ...
Scene 3 (10-15s): visual: ...; narration: ...; on-screen text: ...

Allowed on-screen text only:
- ...
- ...
- ...

Text rules:
Use only the exact on-screen text listed above. only render the exact
provided on-screen text fragments — do not invent extra text. Each on-screen
text fragment is at most max 8 English words. Do not render Chinese
characters. Do not misspell text. If text rendering is uncertain, use
diagrams and icons instead of extra words.

Motion:
Clean, slow, educational motion. Stable camera. No clutter. No dark
cinematic scene. No 3D. No realistic humans.

Negative constraints:
No Chinese characters, no misspelled words, no random letters, no
placeholder text, no dialogue, no podcast, no interview, no two-host
conversation, no stock footage, no clutter, no dark background, no
unrelated objects, no portrait 9:16 framing.

Final rules:
Mandatory duration: 15 seconds. Ignore any conflicting duration instruction
from earlier sections.
Mandatory format: 16:9 landscape, 1920x1080.
English only.
Single narrator monologue only.
The final answer must be correct.
```

The legacy "this v0.6.1 build does not yet generate audio; ... actual
voiceover support depends on the provider" wording is **removed**. v0.6.2
asks the provider for an English narrator voiceover positively; honesty
about audio support belongs in metadata / docs, not in the live prompt.

## 5. Prompt quality gate

`validate_seedance_prompt_quality(prompt, compiled_payload, duration_seconds)`
returns `(passed, reasons, rules)`. The runtime calls it **before every
real APX submit** in `_create_apx_video_job_for_record`. When the gate
fails the runtime:

- creates a `VideoJob` with status `blocked_prompt_quality`,
  stage `blocked_before_submit`, progress 0
- records the structured reasons in `response_payload.prompt_quality`
- maps `VideoHistory.video_status` to `blocked_prompt_quality`
- never calls APX

Default-deny rules (any failure ⇒ block):

- prompt is non-empty and 200 ≤ chars ≤ 12000
- no Chinese / CJK characters
- no banned placeholder strings: `this topic`, `Human review required`,
  `needs human review`, `TBD`, `placeholder`, `does not yet generate audio`
- no standalone `A` / `B` / `AB` / `BA` / `BAB` / `ABA` / `ABAB` / `BABA`
  tokens (word-boundary regex)
- required keywords present: `16:9`, `landscape`, `1920x1080`,
  `english narrator`, `single narrator`, `monologue`, `no dialogue`,
  `no podcast`, `no interview`, `no chinese characters`
- normalized inputs present: `english_subject`, `english_question`,
  `correct_answer`, `narration_script`, `scene_plan`, ≥ 2 entries in
  `allowed_on_screen_text`
- duration coherence: requested duration matches the normalized duration
  AND the prompt mentions it

`APX_VIDEO_ALLOW_FALLBACK_SUBMIT=true` lets operators override the older
fallback-safety check; the new gate is also bypassed when that override
is on. Default is `false`.

## 6. Real per-stage progress run store

The homepage no longer drives a fake `setInterval` through fabricated
stages. Instead:

| Endpoint                                         | Purpose                                  |
| ------------------------------------------------ | ---------------------------------------- |
| `POST /api/video/generate/start`                 | Spawn a worker thread, return `run_id`   |
| `GET /api/video/generate/runs/{run_id}`          | Snapshot of per-stage timing / status    |

Backend stage tuple (`VIDEO_RUN_STAGES`):

1. `validate_topic`
2. `build_llm_content_package`
3. `parse_package_output`
4. `create_video_history_record`
5. `build_video_assets`
6. `compile_seedance_prompt`
7. `validate_prompt_quality`
8. `submit_video_job`
9. `open_video_status_panel`

Each stage records `started_at`, `ended_at`, `duration_ms`, `status`
(`pending` / `running` / `done` / `failed`) and an optional `message`.
The store lives in process memory (`VIDEO_GENERATION_RUNS` +
`VIDEO_GENERATION_RUNS_LOCK`); old runs auto-trim past 32 entries.

The frontend polls every ~1 s and renders the live stage. After the run
completes the homepage hands off to the Video Output tab + VideoJob status
panel — that panel is the only place real APX progress is shown.

## 7. Video Output overlay + history switch

- The progress overlay backdrop is now **fully opaque** (`#0f172a`) so a
  previous record's mp4 cannot bleed through.
- A new `blocked_prompt_quality` overlay state shows the block reason and
  pins progress at 100 %.
- `clearVideoElementSource()` (the existing
  `clearVideoPlayerStateForRecordSwitch()`) is invoked before every new
  generation kicks off and on every history-record switch.
- The Download button binds to the *current* record only (it consults
  `currentVideoRecord` / `currentHistoryId`, never a stale URL from the
  previous record).

## 8. Provider Evidence Summary panel

Above the player, the new `#provider-evidence-panel` displays:

- Provider (`apx_seedance` / `mock`)
- Real API call (`Yes` / `No`)
- Provider Job ID
- Job status
- Remote video URL received (`Yes` / `No` — never the actual URL)
- Local video downloaded
- Local video available
- Local file (filename only — never an absolute path)
- Duration
- Prompt quality (`Passed` / `Blocked`)
- Block reason (only when applicable)

Sourced from `GET /api/video/history/{id}/provider-contract`'s new
`provider_evidence` block. The endpoint never returns API keys, signed
remote video URLs, request headers, or absolute disk paths.

## 9. APX_VIDEO_PROMPT_EXTEND default

`DEFAULT_PROMPT_EXTEND = False`. `config/example.env` recommends `false`.
The provider still honours `APX_VIDEO_PROMPT_EXTEND=true` from the user's
local `.env` — only the project default and recommended setting changed.
This stops APX from auto-rewriting the carefully compiled English prompt
and re-introducing Chinese characters / misspellings / invented on-screen
text.

## 10. Out of scope

v0.6.2 deliberately does **not**:

- introduce Celery / Redis / RQ
- modify the NotebookLM Prompt Mode template
- modify the Prompt Mode database schema
- modify the AI Review rubric
- generate real TTS audio or composite ffmpeg overlays
- change `VIDEO_ASSETS_SCHEMA_VERSION`

If guaranteeing zero typos in on-screen text becomes a requirement,
deterministic subtitle overlay is the next step.
