## 问题背景

在 v0.4.6.7 修复了 datetime 崩溃问题后,AI Review 功能已经可以正常生成并展示。但仍存在以下交互逻辑问题:

### 症状 1:编辑 Prompt 后不稳定触发重新质检

- 用户编辑 Prompt 并保存
- 切换回 AI Review tab
- **有时会自动重新生成,有时不会**
- 触发逻辑不清晰,用户难以预测

### 症状 2:切换操作容易误触发 API 调用

- 用户在 Raw Text / Preview / Overview / AI Review 之间切换
- 切换历史题目后再回来
- 切换版本后查看旧版本
- **这些操作有时会意外触发 AI Review 重新生成**
- 浪费 API 调用,增加等待时间

### 症状 3:缓存逻辑复杂,难以维护

- 前端需要判断 status == none / stale / failed 时是否自动 POST
- 后端需要判断是否已有 completed review
- **逻辑分散在多个地方,容易出现状态不一致**

### 症状 4:用户无法主动控制重新质检

- 当 review 状态为 completed 时,用户无法强制重新生成
- 必须先 Edit Prompt 再保存,才能触发 stale 状态
- **交互流程繁琐,不符合直觉**

---

## 设计目标

将 AI Review 改为**手动触发模式**,明确以下原则:

### 核心原则

✅ **只有用户点击 Re-review 按钮时,才允许重新调用 API**  
✅ **所有其他操作都是只读,只展示数据库缓存结果**  
✅ **逻辑清晰、可控、稳定,用户体验一致**

### 设计思路

1. **新增 Re-review 按钮**
   - 位置:AI Review 表格右上角
   - 功能:强制重新生成 AI Review
   - 样式:小型圆角按钮,带刷新图标

2. **loadReview() 改为只读**
   - 只执行 GET 请求
   - 根据 status 展示不同状态
   - 绝不自动 POST

3. **regenerateReview() 专门处理重新生成**
   - 只由 Re-review 按钮触发
   - POST /api/history/{id}/review?force=true
   - 显示 loading,防止重复点击

4. **状态展示优化**
   - completed:展示表格
   - stale:展示旧表格 + 黄色提示
   - none:展示空状态
   - failed:展示失败状态
   - generating:展示 loading

### 修复 1:重构 loadReview() 为只读模式

**文件**: `web/static/ai_review.js`

**修改前**:

```javascript
async function loadReview(force = false) {
    // ...
    
    // 问题:status == none 或 stale 时自动 POST
    if (status === 'none' || status === 'stale') {
        reviewEl.innerHTML = '<div class="review-loading">Generating AI Review...</div>';
        
        // ← 自动 POST
        const postResponse = await fetch(`/api/history/${historyId}/review`, {
            method: 'POST'
        });
        // ...
    }
}
```

**修改后**:

```javascript
async function loadReview() {
    // 只 GET,不 POST
    const getResponse = await fetch(`/api/history/${historyId}/review`);
    const getData = await getResponse.json();
    const status = getData.status;
    
    // 根据 status 展示不同状态
    if (status === 'completed') {
        renderReviewWithToolbar(getData.review, false);
    } else if (status === 'stale') {
        renderReviewWithToolbar(getData.review, true); // 显示 stale 提示
    } else if (status === 'none') {
        renderReviewEmptyState(); // 显示空状态
    } else if (status === 'failed') {
        renderReviewFailedState(getData.error);
    } else if (status === 'generating') {
        // 显示 loading 并开始轮询
        startReviewPolling(historyId);
    }
}
```

**关键改进**:
- ✅ 删除了所有自动 POST 逻辑
- ✅ status == none 不再自动生成,只展示空状态
- ✅ status == stale 不再自动生成,只展示旧结果 + 提示
- ✅ status == failed 不再自动重试,只展示失败状态
- ✅ 用户体验一致,不再有意外的 API 调用

### 修复 2:新增 regenerateReview() 函数

**文件**: `web/static/ai_review.js`

**新增函数**:

```javascript
async function regenerateReview() {
    if (!currentHistoryId) {
        console.error('No current history ID');
        return;
    }
    
    const historyId = currentHistoryId;
    const reviewEl = document.getElementById('prompt-review');
    
    // 防止重复请求
    const key = `review_${historyId}`;
    if (reviewInFlight.has(key)) {
        console.log('Review regeneration already in flight, skipping duplicate');
        return;
    }
    
    // 显示 loading
    reviewEl.innerHTML = `
        <div class="review-loading">
            <div class="spinner"></div>
            <p>Regenerating AI Review...</p>
            <p style="font-size: 12px; margin-top: 8px;">This may take 20-30 seconds</p>
        </div>
    `;
    
    try {
        reviewInFlight.set(key, true);
        
        // POST force=true
        const postResponse = await fetch(`/api/history/${historyId}/review?force=true`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' }
        });
        
        const postData = await postResponse.json();
        
        // 打印 debug 错误
        if (postData.debug_error) {
            console.error('[AI Review Debug Error]', postData.debug_error);
        }
        
        // 处理结果
        if (postData.status === 'generating') {
            startReviewPolling(historyId);
        } else if (postData.success && postData.review) {
            currentReviewData = postData.review;
            renderReviewWithToolbar(currentReviewData, false);
        } else {
            renderReviewFailedState(postData.error);
        }
        
        reviewInFlight.delete(key);
        
    } catch (error) {
        console.error('Failed to regenerate review:', error);
        renderReviewFailedState('Failed to regenerate AI Review. Please try again.');
        reviewInFlight.delete(key);
    }
}
```

**关键改进**:
- ✅ 专门处理 Re-review 按钮点击
- ✅ 使用 force=true 参数
- ✅ 显示 loading,防止重复点击
- ✅ 成功后更新表格
- ✅ 失败时展示错误或 fallback

## 后端逻辑保持不变

本次重构**只修改前端触发逻辑**,后端 API 行为保持不变:

### GET /api/history/{id}/review (只读)

**行为**:
- 查询数据库,返回 review 状态
- 绝不生成新 review
- 返回 status: none / generating / completed / failed / stale

### POST /api/history/{id}/review?force=true (手动触发)

**行为**:
- force=true → 强制重新生成,覆盖旧结果
- 调用 LLM API
- 成功 → status='completed', review={...}
- 失败 → 尝试 fallback review
- 保存结果到数据库

## 已知限制

1. **Re-review 按钮在 generating 状态下不显示**
   - 当 review 正在生成时,显示 loading 而非工具栏
   - 这是合理的,避免用户在生成过程中再次点击

2. **stale 提示只在有旧 review 时显示**
   - 如果 Prompt 修改后,旧 review 被删除,则显示空状态
   - 这是合理的,避免混淆

3. **切换题目时可能有短暂 loading**
   - GET 请求需要时间(<100ms)
   - 如果网络慢,可能看到短暂 loading
   - 未来可考虑前端缓存优化
