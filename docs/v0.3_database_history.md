# AI Video Prompt Generator v0.3 - Database & History

## Overview

Version 0.3 introduces database-backed history functionality, transforming the AI Video Prompt Generator from a temporary generation tool into a local product prototype with persistent data storage.

## Key Features

### 1. Persistent History Storage
- All successfully generated prompts are automatically saved to a SQLite database
- History survives page refreshes, browser restarts, and server restarts
- Each generation creates a unique record with timestamp and random suffix

### 2. Database Architecture

**Current Database:** SQLite (default)
- Location: `data/prompt_history.db`
- Auto-created on first startup

**Future-Ready:** PostgreSQL support
- Architecture uses SQLAlchemy ORM
- DATABASE_URL environment variable for easy switching
- Repository pattern abstracts database operations

**Database Schema:**

```sql
CREATE TABLE prompt_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    slug TEXT NOT NULL UNIQUE,
    prompt_text TEXT NOT NULL,
    output_dir TEXT NOT NULL,
    model TEXT,
    mode TEXT,
    created_at DATETIME NOT NULL,
    updated_at DATETIME NOT NULL,
    status TEXT NOT NULL DEFAULT 'success',
    metadata_json TEXT
);

CREATE INDEX idx_created_at_desc ON prompt_history(created_at DESC);
CREATE INDEX idx_title_search ON prompt_history(title);
```

### 3. Unique Slug Generation

**Problem:** Chinese titles were being sanitized to generic "video" slugs, causing output directory conflicts.

**Solution:** Each generation now creates a unique slug:
```
Format: {base_slug}_{YYYYMMDD_HHMMSS}_{random_hex}
Example: topic_20260521_162355_a1b2c3
```

Benefits:
- No more output directory collisions
- Each generation is independently tracked
- Repeat generations of same title create new records

### 4. New API Endpoints

#### GET /api/history
List all prompt history records

**Parameters:**
- `limit` (optional, default: 100): Max records to return
- `q` (optional): Search query for title filtering

**Response:**
```json
{
  "success": true,
  "items": [
    {
      "id": 12,
      "title": "为什么宇航员要穿宇航服进入宇宙",
      "slug": "topic_20260521_162355_a1b2c3",
      "created_at": "2026-05-21T16:23:55",
      "model": "gpt-5-chat",
      "status": "success"
    }
  ]
}
```

#### GET /api/history/{id}
Get a single history record with full prompt content

**Response:**
```json
{
  "success": true,
  "item": {
    "id": 12,
    "title": "...",
    "slug": "...",
    "prompt": "...full prompt text...",
    "output_dir": "...",
    "model": "gpt-5-chat",
    "mode": "NotebookLM Prompt Generation",
    "created_at": "...",
    "updated_at": "...",
    "status": "success"
  }
}
```

#### POST /api/generate (Enhanced)
Now saves successful generations to database automatically

**New Response Fields:**
- `id`: Database record ID
- `history_id`: Alias for id
- `created_at`: Generation timestamp

### 5. Frontend History Management

#### Recent Topics Sidebar
- Dynamically loaded from database on page load
- Updates automatically after each new generation
- Click any history item to restore its result
- Shows active item with highlighted background
- Only list area scrolls (header/footer stay fixed)

#### Search Functionality
- Live search with 200ms debounce
- Filters history by title (case-insensitive)
- Supports Chinese and English
- Clear search box to restore full list

#### History Item Interaction
- **Click:** Load historical prompt result (no re-generation)
- **New Chat:** Clear selection, return to initial state
- **Copy/Download:** Work with both new and historical prompts

### 6. Code Structure

```
web/
  db/
    __init__.py          # Module exports
    database.py          # SQLAlchemy engine, session, init
    models.py            # PromptHistory ORM model
    repository.py        # Data access layer (CRUD operations)
  app.py                 # FastAPI routes (uses repository)
  static/
    main.js              # History loading, rendering, search
    index.html           # Dynamic history list container
    style.css            # Scrollable history list styles
```

**Design Principles:**
- **Separation of Concerns:** Database logic isolated from API routes
- **Repository Pattern:** Abstract data access for future DB migrations
- **No Direct SQL in Routes:** All queries through repository layer
- **Environment-Based Config:** DATABASE_URL in .env

### 7. Security & Privacy

**Protected Information:**
- API keys are NEVER saved to database
- API base URLs are NEVER exposed to frontend
- .env contents are NEVER written to database
- Only non-sensitive model names are stored

**Database Access:**
- Database files (.db, .db-shm, .db-wal) in .gitignore
- SQLite file permissions follow system defaults
- Future: PostgreSQL with connection pooling and auth

### 12. Known Limitations

**Current Version (v0.3):**
- No user authentication
- No history deletion UI
- No history editing
- No prompt regeneration from history
- No export/import functionality
- SQLite not suitable for high concurrency
- No database backup automation

**Mitigations:**
- Single local user: Authentication not needed yet
- Manual deletion: Access database directly if needed
- History is append-only by design
- Regenerate: Just enter same title again
- Export: Copy prompt text as needed
- Backup: Copy `data/` directory manually

### 13. Troubleshooting

**Issue: "No module named 'sqlalchemy'"**
```bash
pip install SQLAlchemy>=2.0.0
```

**Issue: Database locked**
- SQLite doesn't support high concurrency
- Solution: Restart server, or migrate to PostgreSQL

**Issue: Old topics still show static data**
- Clear browser cache
- Hard refresh (Cmd+Shift+R)
- Check if `loadHistory()` is being called

**Issue: History not loading**
- Check browser console for errors
- Verify `/api/history` returns data
- Check database file exists: `data/prompt_history.db`

**Issue: Slug conflicts**
- Should not happen with v0.3 unique slugs
- If occurs: Check `generate_unique_slug()` function
- Verify timestamp and random suffix are being added
