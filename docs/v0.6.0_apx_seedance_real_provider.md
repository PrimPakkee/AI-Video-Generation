# v0.6.0 — APX Seedance Real Provider Integration

Status: shipped (2026-06-02)
Predecessor: v0.5.6 (Seedance Prompt Compiler)
Provider module: `web/video_providers/apx_seedance_provider.py`

## Goal

Connect the in-house APX async video gateway (which calls
`doubao-seedance-2.0` under the hood) to the existing Video Mode pipeline so
that the full chain becomes:

```
topic
  → content assets (v0.5.4)
  → seedance_prompt.txt + seedance_payload_preview.json (v0.5.5 / v0.5.6)
  → APX submit  (POST /v1/async/chat)        — v0.6.0
  → APX poll    (GET  /v1/async/results/:id) — v0.6.0
  → download mp4 to outputs/<slug>/video.mp4 — v0.6.0
  → VideoHistory.video_file_path             — v0.6.0
  → frontend plays /api/video/history/:id/asset/video
```

Up through v0.5.6 the system shipped only a *contract adapter* — every
provider call was a dry-run preview and no mp4 ever touched disk. v0.6.0
is the first version to perform real outbound HTTP requests, but only from
inside `apx_seedance_provider.py`, only when the operator explicitly opts
in via `.env`, and only after a fallback-prompt safety check.

### Environment variables

| Name                                  | Default              | Purpose |
| ------------------------------------- | -------------------- | ------- |
| `APX_VIDEO_ENABLED`                   | `false`              | Master switch. When false the dispatcher falls back to Mock. |
| `APX_VIDEO_BASE_URL`                  | `http://apx-api.tal.com` | APX gateway origin. |
| `APX_VIDEO_API_KEY`                   | _(empty)_            | API key. Required when enabled. Never written to DB / metadata / logs. |
| `APX_VIDEO_MODEL`                     | `doubao-seedance-2.0`| Sent in the `X-APX-Model` header and in the JSON body. |
| `APX_VIDEO_DURATION`                  | `5`                  | Seconds. **NOT 60** — the APX gateway expects short clips. |
| `APX_VIDEO_PROMPT_EXTEND`             | `true`               | Forwarded to APX as `prompt_extend`. |
| `APX_VIDEO_POLL_INTERVAL_SECONDS`     | `5`                  | Advisory only — the frontend polls on user click. |
| `APX_VIDEO_TIMEOUT_SECONDS`           | `600`                | Per-request HTTP timeout. |
| `APX_VIDEO_CONFIRM_AFTER_DOWNLOAD`    | `false`              | When true, issue `DELETE /v1/async/results/:id` after a successful download. |
| `APX_VIDEO_ALLOW_FALLBACK_SUBMIT`     | `false`              | When true, bypass the fallback-prompt safety check. |

The provider re-reads `APX_VIDEO_API_KEY` from the environment on every
call, so updating `.env` does not require restarting the FastAPI process.

### State machine

`VideoJob.status` values produced by the APX branch:

```
submitted  → pending → running → succeeded → (download) → succeeded
                                          ↘  (no url)  → succeeded_but_no_video_url
                                  ↘  (raw_status=4)    → failed
blocked_fallback_prompt  (refused before submit)
```

`VideoHistory.video_status` is synced via `_map_job_status_to_video_status`
and now passes `submitted` / `pending` / `running` /
`blocked_fallback_prompt` / `succeeded_but_no_video_url` straight through.

### Submit body

The APX payload is intentionally minimal in v0.6.0:

```json
{
  "model": "doubao-seedance-2.0",
  "prompt": "<compiled Seedance prompt, EN>",
  "duration": 5,
  "prompt_extend": true
}
```

`negative_prompt`, `extra_body`, `img_url`, and `seed` are NOT sent —
those are reserved for a later milestone. The stability check enforces
that only the four allowed keys appear inside `build_submit_payload`.

### Fallback-prompt safety

Real APX submission is refused — even when fully configured — if any of
the following looks like the asset pipeline ran in fallback mode:

- `generation_manifest.json` has `llm_used: false`
- `generation_manifest.json` has `fallback_used: true`
- `seedance_prompt_ready` is not `true`
- the compiled prompt contains the placeholder `需要人工核对` or
  `Human review required`
- `seedance_prompt_debug.json` warnings include the substring `missing`

The provider then persists a job with `status = blocked_fallback_prompt`
and never burns APX credits. Operators can override by setting
`APX_VIDEO_ALLOW_FALLBACK_SUBMIT=true`, but this is intentionally noisy.

### Download safety

`download_video` and `download_cover`:

- reject any URL whose scheme is not `http` or `https`
- sanitize the filename (`[^A-Za-z0-9._-]` → `_`) and refuse anything
  that resolves outside `outputs/<slug>/`
- stream in 64 KiB chunks to `<file>.part` and atomically rename to the
  final filename — a transport error never leaves a half-written mp4 in
  place

### Secret hygiene

- `_scrub_api_key` recursively redacts any dict key matching
  `api-key`, `api_key`, `apikey`, `authorization`, `x-api-key` before
  the payload reaches `request_json` / `response_json`.
- `load_config()` exposes `api_key_configured: bool` instead of the
  raw key.
- The Download All metadata is unchanged from v0.5.6 in terms of
  fields; the v0.6.0 wiring guarantees the API key is never added.

### Stability checks

`check_v060_apx_provider` covers ≥17 sub-checks: provider class & methods

## Manual smoke test

Automatic stability checks intentionally do NOT call the APX gateway —
that has to be done by hand with real credentials. The procedure:

1. Add to `.env`:
   ```
   APX_VIDEO_ENABLED=true
   APX_VIDEO_BASE_URL=http://apx-api.tal.com
   APX_VIDEO_API_KEY=<your key>
   APX_VIDEO_MODEL=doubao-seedance-2.0
   APX_VIDEO_DURATION=5
   APX_VIDEO_PROMPT_EXTEND=true
   ```
2. Start the server: `uvicorn web.app:app --reload --port 8000`
3. Open the UI in Video Mode, type a topic, click Generate.
4. The Video tab should render the status panel with `provider:
   apx_seedance`, `status: submitted`, and a Refresh button.
5. Click Refresh. The status moves through `pending` / `running` and
   eventually to `succeeded`, at which point `video.mp4` appears under
   `outputs/<slug>/` and the player loads
   `/api/video/history/<id>/asset/video`.
6. Verify with `ls outputs/<slug>/video.mp4` and play in the browser.

Failure modes you can test by toggling env vars:

- Unset `APX_VIDEO_ENABLED` → the system falls back to Mock and shows
  `provider_not_configured`.
- Set `APX_VIDEO_API_KEY` to a bogus value → submit returns HTTP 4xx,
  the job lands in `failed` with the redacted response captured.
- Run on a topic where the asset pipeline fell back to placeholder
  content → expect `status = blocked_fallback_prompt` and no real
  network call.
