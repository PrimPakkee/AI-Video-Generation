# v0.4.6 Calibrated AI Review

**Version**: v0.4.6  
**Date**: 2026-05-22  
**Type**: Major Feature Update  
**Status**: Completed

---

## Overview

v0.4.6 addresses a critical product issue in the AI Review feature introduced in v0.4.5: the evaluation system was giving almost all prompts full scores (100/100), making the quality assessment meaningless. This version implements a **Calibrated AI Review** system with strict, evidence-based scoring that provides meaningful differentiation between prompt quality levels.

## Problem Statement

### Issue: AI Review Lacks Differentiation

After v0.4.5 deployment, the AI Review feature was generating scores that were:
- Almost always 100/100 or 99/100
- Not identifying real quality differences between prompts
- Providing generic praise instead of specific, actionable feedback
- Checking only for keyword presence rather than actual quality

**Example symptoms**:
- Prompts with vague visual descriptions: 100/100
- Prompts with generic templates: 100/100
- Prompts with incomplete reasoning: 100/100

This made the AI Review feature useless for quality control.

## Solution: Calibrated Scoring System

### 1. Evidence-Based Evaluation Principles

The new system requires:
- **Concrete evidence** from the prompt text for each score
- **No default full scores** - full score requires demonstrated excellence
- **Quality over keywords** - presence of sections is not enough
- **Balanced feedback** - every comment must mention both strengths AND weaknesses
- **Strict but fair** - don't invent problems, but don't be overly generous

### 2. General Scoring Scale

Defined clear scoring tiers across all dimensions:

| Score Range | Quality Level | Meaning |
|------------|---------------|---------|
| 95-100% | Excellent | Very specific, complete, and directly usable. No meaningful improvement needed. |
| 85-94% | Strong | Mostly complete and usable, but minor gaps or areas for improvement exist. |
| 70-84% | Acceptable | Usable, but several details are generic, incomplete, or need manual refinement. |
| 50-69% | Weak | Important parts are missing, vague, or difficult to execute. |
| Below 50% | Poor | The criterion is mostly not satisfied. |

### 3. Dimension-Specific Deduction Rules

Each of the 8 dimensions now has explicit deduction rules:

#### 1. Completeness (15 points)
- Missing ANY key module (title, question, answer, reasoning, narration, visual style, constraints): **-2 to -5 points**
- Modules present but content is empty or template-like: **max 11/15**
- Modules present but generic/not directly usable: **max 13/15**

#### 2. Logical Correctness (20 points)
- No clear answer provided: **max 12/20**
- Answer and reasoning do not match: **max 10/20**
- Math or logic error present: **max 8/20**
- Reasoning correct but steps too abrupt/incomplete: **max 17/20**

#### 3. NotebookLM Usability (15 points)
- Contains engineering info (output slug, directory, database, API, debug, internal review): **max 10/15**
- Instructions too long but key points unclear: **max 12/15**
- Usable but requires manual cleanup: **max 13/15**

#### 4. Visual Directability (10 points)
- Only generic "white background / hand-drawn style" without scene details: **max 7/10**
- No explanation of how core diagram evolves: **max 7/10**
- No restriction against decorative/inconsistent visuals: **max 8/10**
- Visual descriptions too abstract for NotebookLM: **max 8/10**

#### 5. Short-video Suitability (10 points)
- No strong hook: **max 8/10**
- Pacing too slow or content too long: **max 7/10**
- No clear ending or takeaway: **max 8/10**
- More like a long lecture than a short video: **max 6/10**

#### 6. Single-narrator Compliance (10 points)
- Only mentions "single narrator" but doesn't prohibit multi-person formats: **max 8/10**
- Contains dialogue/host A/B/conversation language: **max 5/10**
- Format might be interpreted as interview by NotebookLM: **max 7/10**

#### 7. Educational Clarity (10 points)
- Explanation too abstract: **max 7/10**
- No step-by-step breakdown: **max 8/10**
- Missing analogies, intuitive examples, or key subtitle suggestions: **max 8/10**
- Explanation correct but not easy to understand: **max 8/10**

#### 8. Risk & Error Control (10 points)
- No restriction against wrong answers or changing the puzzle: **max 7/10**
- No visual consistency constraints: **max 8/10**
- No requirement for answer-visual alignment: **max 8/10**
- Constraints too generic: **max 8/10**

### 4. Total Score Calibration

Recalibrated total score interpretation:

| Total Score | Quality Level | Description |
|------------|---------------|-------------|
| 98-100 | Exceptional | Nearly publication-ready, no meaningful improvement needed. |
| 94-97 | Excellent | Only very minor refinements needed. |
| 88-93 | Strong | Strong and usable, but still has some improvement areas. |
| 80-87 | Good Draft | Usable but needs refinement. |
| 70-79 | Needs Improvement | Noticeable improvement required. |
| Below 70 | Weak/Incomplete | Significant rework needed. |

**Expected distribution**:
- Ordinary acceptable prompts: **80-88**
- Good quality prompts: **89-94**
- Excellent prompts with minimal issues: **95-98**
- Perfect prompts: **100** (extremely rare)

### 5. Technical Implementation

#### Schema Versioning
- Added `review_schema_version` field to `prompt_reviews` table
- Default value: `'v0.4.6_calibrated'`
- Old reviews without schema version or with different version are marked as outdated
- System automatically prompts regeneration for outdated reviews

#### Temperature Adjustment
- Changed LLM temperature from **0.3 → 0** for consistent, deterministic evaluation
- Reduces random variation in scoring

#### Comment Quality Requirements
- Comments must be **specific**, not generic praise
- Must mention **both strengths AND weaknesses** (if applicable)
- Example: "The prompt includes the main required sections and clear narration structure, but the visual progression remains somewhat generic and would benefit from more scene-specific details for NotebookLM execution."

## Implementation Details

### Files Modified

1. **scripts/llm_topic_enhancer.py**
   - Replaced `_build_review_user_prompt()` method with calibrated version
   - Added strict evaluation principles, scoring scale, and deduction rules
   - Changed temperature to 0 in `review_prompt()` method

2. **web/db/models.py**
   - Added `review_schema_version` field to `PromptReview` model
   - Default: `'v0.4.6_calibrated'`

3. **web/db/repository_review.py**
   - Updated `create_review()` to accept `schema_version` parameter
   - Added `is_review_outdated()` method to check schema version
   - Outdated reviews trigger regeneration prompt

4. **web/app.py**
   - GET `/api/history/{history_id}/review` checks for outdated reviews
   - Returns `has_review: false, reason: "outdated_schema"` for old reviews
   - POST endpoint saves with `schema_version='v0.4.6_calibrated'`

### Migration Strategy

Old reviews (v0.4.5 or earlier) are not automatically deleted. Instead:
- Frontend checks `is_review_outdated()` before displaying
- If outdated, UI shows "Generate AI Review" button (as if no review exists)
- User can regenerate with new calibrated rubric
- Old review data remains in database for historical reference

## Testing & Validation

### Test Cases

1. **Excellent Prompt** (Expected: 94-98)
   - All modules present with specific, executable content
   - Clear logic with step-by-step reasoning
   - Concrete visual descriptions with scene progression
   - Strong hook and pacing
   - Explicit single-narrator requirement
   - Should NOT get 100 unless truly flawless

2. **Good Prompt** (Expected: 85-93)
   - All key modules present
   - Logic correct but some steps abrupt
   - Visual style specified but some scenes generic
   - Good structure with minor refinement areas

3. **Acceptable Prompt** (Expected: 75-84)
   - Most modules present
   - Some template-like sections
   - Visual descriptions present but abstract
   - Usable with manual refinement needed

4. **Weak Prompt** (Expected: 50-69)
   - Missing key modules or placeholders only
   - Logic incomplete or unclear
   - Generic visual descriptions
   - Poor short-video fit

### Validation Checklist

- [ ] Old full-score reviews are marked as outdated
- [ ] New reviews use temperature 0
- [ ] Scores show meaningful differentiation
- [ ] Comments mention both strengths and weaknesses
- [ ] Total score distribution matches expectations
- [ ] Schema version correctly saved as 'v0.4.6_calibrated'

## Expected Impact

### Before v0.4.6 (v0.4.5 Scoring)
- 90%+ prompts: 98-100 score
- Generic comments: "The prompt is complete and clear"
- No actionable feedback
- Quality differences invisible

### After v0.4.6 (Calibrated Scoring)
- Score distribution: 70-95 for most prompts
- Specific comments with evidence and improvement areas
- Actionable feedback for refinement
- Clear quality differentiation

## Notes

- **Not about lowering scores**: Goal is differentiation, not artificial penalty
- **100/100 should be rare**: Reserved for truly exceptional, publication-ready prompts
- **Backward compatible**: Old reviews remain in database but marked outdated
- **Regeneration required**: Users must manually regenerate reviews for calibrated scores
