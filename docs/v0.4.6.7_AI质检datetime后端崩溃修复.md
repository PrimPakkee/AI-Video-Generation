### 症状 1:所有 AI Review 接口返回 500 Internal Server Error

- 用户点击 "AI Review" 按钮
- 页面显示加载动画
- 几秒后显示:**"AI Review generation failed. Please try again."**
- **影响范围**:所有题目都无法生成 AI Review

### 症状 2:Try Again 按钮无效

- 用户点击 "Try Again" 按钮
- 页面显示 "Regenerating AI Review..."
- 后端确实收到 POST 请求:`POST /api/history/{id}/review?force=true`
- **但接口直接返回 500 错误**
- 页面再次显示失败提示

### 症状 3:后端终端显示关键错误

```
[AI Review Outer Error - history_id=14] local variable 'datetime' referenced before assignment
```

**关键信息**:
- 错误出现在 "Outer Error"(外层异常捕获)
- 错误类型:`local variable 'datetime' referenced before assignment`
- **这是 Python 变量作用域错误,不是 LLM 或 JSON 解析问题**

## 根本原因分析

### 原因:Python 变量作用域冲突

**问题代码**:

`web/db/repository_review.py` 文件中存在以下模式:

```python
# 文件顶部 (第 6 行)
from datetime import datetime

class PromptReviewRepository:
    
    @staticmethod
    def get_review_status(db: Session, history_id: int, schema_version: str = 'v0.4.6_calibrated') -> str:
        # ... 省略前面部分 ...
        
        # 第 198-200 行:在 if 块内部重新导入
        if review.status == 'generating':
            from datetime import datetime, timedelta  # ← 问题!
            timeout_threshold = datetime.utcnow() - timedelta(minutes=5)
            if review.updated_at and review.updated_at < timeout_threshold:
                # Mark as failed
                PromptReviewRepository.mark_review_failed(...)
                return 'failed'
        
        # 第 227 行:在 if 块外部使用 datetime
        db.query(PromptReview).filter(...).update({
            'status': status,
            'updated_at': datetime.utcnow()  # ← 崩溃!
        })
```

**Python 作用域规则**:

1. **Python 在编译时扫描整个函数**
   - 当 Python 看到函数内部有 `from datetime import datetime` 时
   - 它会把 `datetime` 识别为**整个函数作用域的局部变量**
   - 即使这个 import 在 if 块内部

2. **局部变量必须先赋值后使用**
   - 如果 if 条件不成立(`review.status != 'generating'`)
   - if 块内的 `from datetime import datetime, timedelta` 不会执行
   - `datetime` 局部变量没有被赋值
   - 但后续代码(第 227 行)尝试使用 `datetime.utcnow()`
   - **触发 "local variable 'datetime' referenced before assignment"**

3. **全局 datetime 被屏蔽**
   - 虽然文件顶部有 `from datetime import datetime`
   - 但函数内部的 `from datetime import ...` 把 `datetime` 变成了局部变量
   - 函数内部无法访问全局的 `datetime`

**时间线**:

1. T=0s:用户点击 "AI Review"
2. T=0s:后端调用 `PromptReviewRepository.get_review_status()`
3. T=0s:假设 `review.status = 'failed'`(不是 'generating')
4. T=0s:if 块不执行,`datetime` 局部变量未被赋值
5. T=0s:代码执行到第 227 行:`datetime.utcnow()`
6. T=0s:**Python 抛出异常**:`local variable 'datetime' referenced before assignment`
7. T=0s:外层 except 捕获异常,打印 "[AI Review Outer Error]"
8. T=0s:接口返回 500
9. T=1s:用户看到失败提示

## 修复内容

### 修复 1:统一 datetime 导入方式

**文件**:`web/db/repository_review.py`

**修改前**:

```python
# 第 6 行
from datetime import datetime

# 第 199 行 (函数内部)
if review.status == 'generating':
    from datetime import datetime, timedelta
    ...

# 第 255 行 (函数内部)
if existing.status == 'generating':
    from datetime import datetime, timedelta
    ...
```

**修改后**:

```python
# 第 6 行 - 统一在文件顶部导入
from datetime import datetime, timedelta

# 第 198 行 (删除条件导入)
if review.status == 'generating':
    timeout_threshold = datetime.utcnow() - timedelta(minutes=5)
    ...

# 第 254 行 (删除条件导入)
if existing.status == 'generating':
    timeout_threshold = datetime.utcnow() - timedelta(minutes=5)
    ...
```

**关键改进**:
- ✅ 在文件顶部统一导入 `datetime` 和 `timedelta`
- ✅ 删除函数内部的重复 import
- ✅ `datetime` 和 `timedelta` 成为模块级全局变量
- ✅ 所有函数都可以直接使用,无作用域冲突

### 修复 2:增强错误日志(添加完整 traceback)

**文件**:`web/app.py`

## Python 变量作用域规则总结

### 规则 1:函数内的 import 会创建局部变量

```python
# 错误示例
def my_function():
    if some_condition:
        from datetime import datetime  # datetime 成为局部变量
    
    # 如果 some_condition 为 False,这里会报错
    now = datetime.utcnow()  # UnboundLocalError
```

### 规则 2:Python 在编译时确定变量作用域

- Python 不会在运行时动态改变变量作用域
- 只要函数内部有 `from xxx import yyy`,`yyy` 就是局部变量
- 即使这个 import 在 if/else/try 块内部

### 规则 3:局部变量会屏蔽全局变量

```python
# 文件顶部
from datetime import datetime

def my_function():
    # 即使文件顶部已经导入,这里仍会创建局部变量
    if some_condition:
        from datetime import datetime, timedelta
    
    # datetime 是局部变量,无法访问全局 datetime
    now = datetime.utcnow()  # 如果 if 不执行,报错
```

### 最佳实践

✅ **在文件/模块顶部统一导入**:

```python
# 文件顶部
from datetime import datetime, timedelta
import json
from typing import Optional

# 函数内部直接使用
def my_function():
    now = datetime.utcnow()
    delta = timedelta(minutes=5)
    ...
```

❌ **不要在函数内部 import**(除非确实需要延迟导入):

```python
# 不要这样做
def my_function():
    from datetime import datetime  # ← 避免
    now = datetime.utcnow()
```
