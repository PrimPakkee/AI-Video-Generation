# Legacy Skill Analysis - 旧版 Skill 分析与本项目的关系

## 文档说明

本文档分析旧版 AI 教育短视频生产 skill 的目标、流程、问题，以及本项目（AI Educational Video Workflow Engine）如何吸收其价值并改进。

---

## 一、旧版 Skill 的目标

旧版 skill 的核心目标是：**将 AI 教育短视频生产流程尽量自动化**，从选题到最终视频输出，减少人工干预。

具体目标包括：
1. 自动化脚本生成
2. 自动化视觉素材生成
3. 自动化旁白和 BGM
4. 自动化视频合成
5. 输出可直接发布的 mp4 视频

---

## 二、旧版 Skill 的流程概览

旧版 skill 大致覆盖以下流程：

### 2.1 输入层
- **选题输入**：从选题库或人工输入题目

### 2.2 脚本生成
- **题目重写**：用 ChatGPT 优化题目表述
- **脚本生成**：生成视频脚本（包括钩子、题面、推理、答案、总结）
- **旁白文案**：生成适合 TTS 的旁白文案

### 2.3 视觉素材生成
- **Gamma / PPT 生成**：使用 Gamma 生成静态图片或 PPT
- **图像素材生成**：调用 DALL-E / Midjourney 生成图像
- **图片转视频**：使用即梦 AI 等工具让静态图片动起来

### 2.4 音频生成
- **旁白 Voiceover**：使用 TTS（ElevenLabs / Azure TTS）生成旁白音频
- **BGM**：添加背景音乐（从素材库选择或生成）

### 2.5 视频合成
- **ffmpeg 合成**：将视觉素材、旁白音频、BGM 合成为视频
- **字幕生成**：根据旁白生成字幕并烧录到视频
- **最终输出**：生成 mp4 视频文件

### 2.6 后处理
- **人工调整**：在剪映中微调（过渡效果、字幕位置、音量平衡）
- **发布**：上传到 TikTok / YouTube Shorts / Instagram Reels

## 三、旧版 Skill 的问题

尽管旧版 skill 有端到端的愿景，但在实际使用中遇到了诸多问题：

### 3.1 效果不稳定
- **生成结果不可控**：每次生成的视频风格、质量、结构都不一致
- **视觉风格漂移**：Gamma / DALL-E 生成的图像风格不统一，有时是卡通风格，有时是写实风格
- **旁白语气不一致**：TTS 生成的旁白有时过于严肃，有时过于轻松
- **答案正确性无法保证**：有时生成的答案逻辑错误，但没有人工校验机制

### 3.2 流程复杂
- **工具链过长**：ChatGPT → Gamma → 即梦 AI → TTS → ffmpeg → 剪映，链条太长，任何一个环节出错都会导致整个流程失败
- **依赖外部工具**：依赖 NotebookLM、Gamma、即梦 AI、剪映等外部工具，没有统一的工作流引擎
- **中间文件管理混乱**：脚本、图片、音频、视频片段散落在不同文件夹，难以追溯和复用

### 3.3 过于运营化
- **流程不标准**：每次生产视频的流程都不一样，依赖人工判断和调整
- **难以复用**：生成过的素材和脚本难以复用，每次都从头开始
- **无法批量生产**：只能一条一条做，无法批量处理选题库

### 3.4 依赖人工搬运
- **人工复制粘贴**：需要在多个工具之间反复复制粘贴（ChatGPT → NotebookLM → 剪映）
- **人工调整**：每个环节都需要人工检查和调整，效率低下
- **人工质量检查**：没有自动化的质量检查机制，完全依赖人工

### 3.5 风格不可控
- **缺乏统一的风格指南**：没有明确的 Think Academy AI 教育短视频风格规范
- **风格不一致**：有时生成双人对话，有时单人旁白；有时黑色背景，有时白色背景
- **关键元素缺失**：没有强调 single narrator、white background、yellow highlight boxes 等关键风格元素

### 3.6 工具割裂
- **NotebookLM / Gamma / 即梦 / 剪映之间割裂**：每个工具都是独立的，没有统一的数据格式和接口
- **无法追溯**：生成的视频无法追溯到原始脚本和素材
- **无法 A/B 测试**：难以对比不同风格的效果

### 3.7 逻辑与画面脱节
- **难以保证题目逻辑、旁白和画面严格对应**：脚本、旁白、画面分别生成，难以保证三者同步
- **画面与推理过程不匹配**：有时画面很炫，但与推理逻辑无关

### 3.8 不适合作为产品
- **代码质量低**：旧版 skill 更像一次性脚本，缺乏模块化设计
- **难以维护**：代码混乱，难以扩展和优化
- **缺乏文档**：没有完整的产品文档、技术文档、使用文档

## 四、本项目如何吸收旧 Skill 的价值

本项目（AI Educational Video Workflow Engine）吸收了旧版 skill 的核心价值，并进行了系统化改进：

### 4.1 保留端到端思路
- ✅ 保留旧版 skill 的 **端到端视频生产思路**
- ✅ 从选题到 mp4 视频的完整流程
- ✅ 尽量减少人工干预

### 4.2 结构化约束内容
- ✅ **先用结构化 video package 约束内容**
- ✅ 每条视频必须包含 15 个标准字段（详见 `docs/prompt_schema.md`）
- ✅ 确保题目、答案、推理、旁白、字幕、分镜、画面说明都正确
- ✅ 在生成视频前，先生成完整的 video package，方便人工检查和修改

### 4.3 分阶段迭代
- ✅ **不是一步到位，而是分阶段迭代**
- ✅ V0：文档和模板体系（已完成）
- ✅ V1：自动生成 video package（CLI 工具 + ChatGPT API）
- ✅ V2：批量处理选题库
- ✅ V3：接入 TTS、视觉生成、视频生成、ffmpeg 合成
- ✅ V4：端到端自动化

### 4.4 质量优先
- ✅ **质量优先于速度**
- ✅ 每个阶段都有明确的质量标准和检查机制
- ✅ 答案逻辑正确性是硬性要求
- ✅ 风格一致性是硬性要求

### 4.5 可维护性
- ✅ **从"人工运营流程"升级为"可维护的视频工作流引擎"**
- ✅ 模块化设计（`scripts/modules/`）
- ✅ 完整的产品文档和技术文档
- ✅ 清晰的版本路线图和技术路线
- ✅ 代码规范和注释

## 五、本项目和旧 Skill 的核心区别

| 维度 | 旧版 Skill | 本项目（AI Educational Video Workflow Engine） |
|------|-----------|-----------------------------------------------|
| **目标** | 端到端自动化，一步到位 | 分阶段迭代，先标准化再自动化 |
| **流程** | 从选题直接到视频 | 先生成 video package，再生成视频 |
| **质量控制** | 缺乏，依赖人工 | 结构化 Schema + 自动质量检查 + 人工审核 |
| **风格规范** | 不明确 | 详细的 Think Academy AI 风格指南 |
| **批量生产** | 难以批量 | 支持批量处理选题库 |
| **可维护性** | 一次性脚本 | 模块化设计，完整文档 |
| **工具依赖** | 依赖外部工具（Gamma、即梦、剪映） | 尽量自主，减少外部依赖 |
| **成本** | 不可控 | 可控（Template Mode 零成本，LLM Mode 可配置） |

## 六、核心风格强化

本项目特别强调 **Think Academy AI 教育短视频风格**，这是旧版 skill 缺失的核心部分：

### 6.1 叙事形式
- ⭐ **Single narrator / 单人旁白 / monologue narration**
- ❌ **不要双人对话、访谈、播客、多人讨论**

### 6.2 视觉风格
- ⭐ **White or light graph-paper background**（白色或浅色方格纸背景）
- ⭐ **Clean doodle / hand-drawn educational style**（简洁涂鸦/手绘教育风格）
- ⭐ **Cute but not childish icons**（可爱但不幼稚的图标）
- ❌ **不要黑色背景、写实照片、复杂纹理**

### 6.3 字幕设计
- ⭐ **Large centered English captions**（大而居中的英文字幕）
- ⭐ **Yellow highlight boxes for key words**（关键词用黄色高亮框）
- ❌ **不要小字幕、不突出关键词**

### 6.4 动画风格
- ⭐ **Simple motion**（简单动效：淡入淡出、缩放、平移、手绘动画）
- ❌ **不要复杂 3D 动画、旋转、爆炸、闪烁**

### 6.5 逻辑正确性
- ⭐ **题目逻辑正确性是硬性要求**
- ⭐ **不能为了传播效果牺牲答案准确性**
- ⭐ **推理过程必须完整、清晰、可验证**

### 6.6 画面与推理对应
- ⭐ **画面必须服务推理过程**
- ⭐ **每个推理步骤都有对应的画面和字幕**
- ⭐ **核心图示前后一致**
- ❌ **不要为了炫酷而加入无关画面**

## 七、分阶段迭代的优势

本项目采用 V0 → V1 → V2 → V3 → V4 的分阶段迭代策略，相比旧版 skill 有以下优势：

### 7.1 降低风险
- 每个阶段都有明确的交付物和成功标准
- 可以在每个阶段及时发现问题并调整方向
- 不会因为一步到位而导致项目失败

### 7.2 快速验证
- V0 阶段验证文档和模板设计
- V1 阶段验证 CLI 工具和 API 集成
- V2 阶段验证批量处理和数据库存储
- V3 阶段验证 TTS、视觉生成、视频合成
- V4 阶段验证端到端自动化

### 7.3 灵活调整
- 可以根据实际使用反馈调整优先级
- 可以选择性实现某些功能（例如：先不做图片生成，直接用素材库）
- 可以根据成本和质量平衡选择不同的 API

### 7.4 团队协作
- 产品经理可以在 V0 阶段参与文档和模板设计
- 内容运营可以在 V1 阶段参与测试和反馈
- 技术开发可以在 V2-V4 阶段专注于代码实现

## 八、总结

| 方面 | 旧版 Skill | 本项目 |
|------|-----------|--------|
| **愿景** | ✅ 端到端自动化 | ✅ 端到端自动化 |
| **实现方式** | ❌ 一步到位，容易失败 | ✅ 分阶段迭代，逐步验证 |
| **质量控制** | ❌ 缺乏 | ✅ 结构化 + 自动检查 + 人工审核 |
| **风格规范** | ❌ 不明确 | ✅ 详细的 Think Academy AI 风格指南 |
| **可维护性** | ❌ 一次性脚本 | ✅ 模块化设计，完整文档 |
| **批量生产** | ❌ 难以批量 | ✅ 支持批量处理 |
| **成本可控** | ❌ 不可控 | ✅ Template Mode（零成本）+ LLM Mode（可配置） |
| **适合人群** | ❌ 只有技术人员 | ✅ 产品经理、内容运营、技术开发都可参与 |

**核心改进**：
1. 先标准化（V0），再自动化（V1-V4）
2. 结构化约束内容（15 个标准字段）
3. 详细的风格指南（Think Academy AI 风格）
4. 分阶段迭代，降低风险
5. 从"人工运营流程"升级为"可维护的视频工作流引擎"
