## 问题背景

在 v0.4.6.4 修复了 Try Again 按钮和错误诊断后,AI Review 功能仍存在严重问题:

### 症状 1:大量题目生成失败,失败率居高不下

- 用户点击 AI Review,大概率直接失败
- 失败提示: "AI Review generation failed. Please try again."
- Try Again 按钮虽然可以重试,但大概率仍然失败
- **影响范围**:大部分历史题目无法生成 AI Review

### 症状 2:Try Again 多次重试仍然失败

- 用户点击 Try Again 后,页面显示 "Regenerating AI Review..."
- 后端确实调用了 LLM API
- 但仍然失败,console 显示 JSON 解析错误
- **用户体验极差**,功能几乎不可用

### 症状 3:错误日志难以分析

- 后端终端打印的错误信息不够详细
- 无法直接查看 LLM 返回的原始 JSON
- 无法快速定位是哪个字段出问题
- **排查效率低**

---

## 根本原因分析

### 原因 1:当前协议让 LLM 生成完整 5 列表格,包含大量固定文本

**当前协议**:

```json
{
  "rows": [
    {
      "criterion": "Completeness",
      "weight": "15%",
      "evaluation_focus": "Check whether the prompt contains all necessary modules, including title, topic, target platform, target audience, video length, core concept, hook, full puzzle setup, question, correct answer, reasoning, narration, on-screen text, visual style, format requirements, constraints, and call to action.",
      "max_score": 15,
      "score": 13,
      "llm_score": "13/15",
      "llm_comment": "..."
    },
    // 7 more dimensions...
  ],
  "total_score": 89,
  "overall_review": "..."
}
```

**问题分析**:

1. **大量固定文本重复生成**
   - `criterion`, `weight`, `evaluation_focus` 是固定的
   - 每次生成都要求 LLM 完整输出这些固定文本
   - 增加 token 消耗,增加失败概率

2. **LLM 容易出现格式问题**
   - 固定文本中包含长句子,容易被 LLM 改写
   - 例如:`"evaluation_focus": "Check whether..."`
   - LLM 可能返回:`"evaluation_focus": "Checks if the prompt..."`
   - 导致前后不一致,虽然意思相同但字符串不匹配

3. **JSON 结构复杂**
   - 8 个维度 × 6 个字段 = 48 个字段
   - 容易缺失字段、多字段、字段顺序错误
   - `llm_score` 格式要求严格: `"13/15"` (不能是 `"13 / 15"` 或 `"13/15分"`)

4. **提示词过长**
   - 当前提示词约 3000+ 字符
   - 包含大量示例 JSON,重复描述评分规则
   - **增加 API 调用成本和耗时**

### 原因 2:缺少调试工具

**问题**:
- 当 AI Review 失败时,无法查看 LLM 返回的原始 JSON
- 无法确认是 LLM 输出问题还是后端解析问题
- 无法快速重现和修复

### 原因 3:无法批量清理失败记录

**问题**:
- 大量题目的 AI Review 状态为 `failed`
- 用户需要逐个点击 Try Again
- 没有批量重置工具
- **影响测试效率**

---

## 修复方案

### 方案核心思想:前后端分离固定数据与可变数据

**原则**:
- 固定的质检维度定义(Criterion, Weight, Evaluation Focus)应由后端维护
- LLM 只负责生成可变部分(Score, Comment)
- 后端负责合并固定结构与 LLM 输出

**新协议设计**:

#### 后端定义固定 rubric (web/db/review_rubric.py 或 scripts/llm_topic_enhancer.py)

```python
AI_REVIEW_RUBRIC = [
    {
        "key": "completeness",
        "criterion": "Completeness",
        "weight": "15%",
        "max_score": 15,
        "evaluation_focus": "Check whether the prompt contains all necessary modules..."
    },
    # 7 more dimensions...
]
```

#### LLM 只返回简化 JSON

```json
{
  "scores": [
    {
      "key": "completeness",
      "score": 13,
      "comment": "The prompt includes the main required sections..."
    },
    {
      "key": "logical_correctness",
      "score": 18,
      "comment": "Logic is sound but reasoning steps could be more detailed."
    }
    // 6 more...
  ],
  "overall_review": "Strong prompt with minor refinements needed."
}
```

#### 后端合并生成完整表格

```python
def build_review_table_from_llm_scores(llm_data):
    """将 LLM 简化输出与固定 rubric 合并"""
    rows = []
    for dim in AI_REVIEW_RUBRIC:
        key = dim["key"]
        llm_score_data = find_score_by_key(llm_data["scores"], key)
        
        rows.append({
            "criterion": dim["criterion"],          # 固定
            "weight": dim["weight"],                # 固定
            "evaluation_focus": dim["evaluation_focus"],  # 固定
            "max_score": dim["max_score"],          # 固定
            "score": llm_score_data["score"],       # LLM 生成
            "llm_score": f"{score}/{max_score}",    # 后端计算
            "llm_comment": llm_score_data["comment"]  # LLM 生成
        })
    
    return {"rows": rows, "total_score": sum_scores(), "overall_review": llm_data["overall_review"]}
```

### 修复 3:创建 rubric 合并函数

**文件**: `scripts/llm_topic_enhancer.py`

**新增方法**: `_build_review_table_from_llm_scores(llm_data)`

```python
def _build_review_table_from_llm_scores(self, llm_data):
    """
    Merge LLM simplified output with fixed rubric to build complete review table
    
    Args:
        llm_data: LLM output in format:
            {
                "scores": [{"key": "completeness", "score": 13, "comment": "..."}],
                "overall_review": "..."
            }
    
    Returns:
        Complete review data in frontend-compatible format
    """
    if not isinstance(llm_data, dict):
        raise ValueError("LLM data must be a dict")
    
    if "scores" not in llm_data or not isinstance(llm_data["scores"], list):
        raise ValueError("LLM data must contain 'scores' array")
    
    # Build key-to-score mapping
    score_map = {}
    for item in llm_data["scores"]:
        key = item.get("key")
        score = item.get("score")
        comment = item.get("comment", "")
        if key:
            score_map[key] = {"score": score, "comment": comment}
    
    # Merge with fixed rubric
    rows = []
    total_score = 0
    
    for dim in AI_REVIEW_RUBRIC:
        key = dim["key"]
        score_data = score_map.get(key, {"score": 0, "comment": "No comment provided."})
        score = score_data["score"]
        comment = score_data["comment"]
        
        # Validate and normalize score
        if not isinstance(score, int):
            try:
                score = int(score)
            except (ValueError, TypeError):
                score = 0
        
        # Ensure score within bounds
        max_score = dim["max_score"]
        if score < 0:
            score = 0
        if score > max_score:
            score = max_score
        
        total_score += score
        
        # Build complete row
        rows.append({
            "criterion": dim["criterion"],
            "weight": dim["weight"],
            "evaluation_focus": dim["evaluation_focus"],
            "max_score": max_score,
            "score": score,
            "llm_score": f"{score}/{max_score}",
            "llm_comment": comment if comment else "No comment provided."
        })
    
    # Get overall review
    overall_review = llm_data.get("overall_review", "")
    if not overall_review:
        # Auto-generate if missing
        if total_score >= 95:
            overall_review = f"Excellent prompt with a score of {total_score}/100."
        elif total_score >= 85:
            overall_review = f"Strong prompt with a score of {total_score}/100."
        elif total_score >= 70:
            overall_review = f"Acceptable prompt with a score of {total_score}/100."
        else:
            overall_review = f"Prompt scored {total_score}/100."
    
    return {
        "rows": rows,
        "total_score": total_score,
        "overall_review": overall_review
    }
```

**关键改进**:
- ✅ 将 LLM 的简化输出与固定 rubric 合并
- ✅ 自动计算 `llm_score` 字符串(`"13/15"`)
- ✅ 自动计算 `total_score`
- ✅ 容错处理:缺失字段自动补充默认值
- ✅ Score 范围校验:[0, max_score]

```python
@app.get("/api/history/{history_id}/review/debug")
async def get_review_debug(
    history_id: int,
    db: Session = Depends(get_db)
) -> Dict[str, Any]:
    """
    Get detailed debug information for AI Review (for development/debugging only)
    
    Returns:
        - Review database record (status, timestamps, error messages)
        - Raw review JSON
        - History record info (version, prompt hash)
        - Schema version
    """
    try:
        from web.db.repository_review import PromptReviewRepository
        
        # Check if history record exists
        record = PromptHistoryRepository.get_history_record(db, history_id)
        if not record:
            return JSONResponse(
                status_code=404,
                content={
                    "success": False,
                    "error": f"History record {history_id} not found"
                }
            )
        
        # Get review record (if exists)
        review = PromptReviewRepository.get_review_by_history_id(db, history_id)
        
        debug_info = {
            "success": True,
            "history_id": history_id,
            "history_info": {
                "prompt_id": record.prompt_id,
                "version": record.version,
                "prompt_hash": record.prompt_hash,
                "created_at": record.created_at.isoformat() if record.created_at else None,
                "updated_at": record.updated_at.isoformat() if record.updated_at else None
            }
        }
        
        if review:
            debug_info["review_record"] = {
                "id": review.id,
                "status": review.status,
                "schema_version": review.review_schema_version,
                "created_at": review.created_at.isoformat() if review.created_at else None,
                "updated_at": review.updated_at.isoformat() if review.updated_at else None,
                "error_message": review.error_message if hasattr(review, 'error_message') else None
            }
            
            # Parse review JSON
            if review.review_json:
                try:
                    review_data = json.loads(review.review_json)
                    debug_info["review_data"] = review_data
                    debug_info["review_json_length"] = len(review.review_json)
                except Exception as parse_error:
                    debug_info["review_data"] = None
                    debug_info["review_json_raw"] = review.review_json[:1000]
                    debug_info["parse_error"] = str(parse_error)
            else:
                debug_info["review_data"] = None
        else:
            debug_info["review_record"] = None
            debug_info["review_data"] = None
            debug_info["message"] = "No review record found for this history_id"
        
        return debug_info
    
    except Exception as e:
        return JSONResponse(
            status_code=500,
            content={
                "success": False,
                "error": f"Failed to retrieve review debug info: {str(e)}"
            }
        )
```

## 已知限制

1. **仍然需要 LLM 返回 8 个维度**
   - 如果 LLM 只返回 7 个或 9 个,仍会失败
   - 这是合理的,因为评分必须包含所有维度

2. **调试接口不适合生产环境**
   - 返回内部数据库结构
   - 建议仅在开发环境使用
   - 未来可添加权限控制

3. **批量重置脚本是临时工具**
   - 不适合频繁使用
   - 未来应优化失败率,减少需要重置的场景

---

## 未来改进方向

1. **自动重试机制**
   - LLM 调用失败时自动重试 1-2 次
   - 减少用户手动 "Try Again" 的次数

2. **增量生成**
   - 将 8 个维度分成 2 次 API 调用
   - 进一步降低单次调用失败的影响

3. **Review 质量监控**
   - 统计各题目的 review 成功率
   - 识别哪些类型的 prompt 容易失败
   - 针对性优化 prompt 或 rubric

4. **更智能的错误恢复**
   - 当某个维度的 score 缺失时,使用默认值(0 分)
   - 不因单个维度失败而导致整体失败
