# AI Video Prompt Generator v0.3.2 - History Management Enhancement

## Overview

Version 0.3.2 introduces comprehensive history management features, transforming the tool into a production-ready application with version control, soft delete, and advanced filtering capabilities.

## Key Features

### 1. Prompt Version Management

**Problem Solved:** Multiple generations of the same topic created scattered history entries.

**Solution:** Automatic version grouping based on normalized title matching.

**How it works:**
- When generating a prompt, the system normalizes the title (lowercase, trim spaces, remove punctuation)
- If a non-deleted record with the same normalized title exists, create a new version in the same topic group
- Otherwise, create a new topic group
- Each topic group has a unique `topic_group_id` (UUID)
- Versions are numbered sequentially: V1, V2, V3, etc.

**User Experience:**
- Left sidebar shows ONE entry per topic (latest version)
- Multiple versions shown as badge: "V2", "V3"
- Click topic → opens latest version
- Version selector in result page lets you switch between versions
- No need to re-run LLM when switching versions

**Example:**
```
User generates: "为什么盲盒越到最后越难集齐"
→ Creates topic_group_id: abc123, version_number: 1

User generates again: "为什么盲盒越到最后越难集齐"
→ Uses topic_group_id: abc123, version_number: 2

Left sidebar shows:
  为什么盲盒越到最后越难集齐 [V2]
```

### 2. Rename History

**Feature:** Rename any topic group (all versions renamed together).

**UI:**
- Three-dot menu → "重命名"
- Title becomes editable input
- Enter or blur to save
- Esc to cancel
- Empty title cancels rename

**Backend:**
- `PATCH /api/history/group/{topic_group_id}/rename`
- Updates `title` and `title_normalized` for all versions in group
- Prompt content unchanged

### 3. Soft Delete & Trash

**Feature:** Deleted topics move to trash instead of permanent deletion.

**Soft Delete Flow:**
1. Click three-dot menu → "删除对话"
2. Confirmation dialog: "确认删除吗？删除后的题目将会在废纸篓中保留。"
3. Click "确认删除" → all versions in group get `deleted_at` timestamp
4. Topic removed from Recent Topics
5. Topic appears in Trash

**Trash Mode:**
- Click trash icon in Recent Topics header
- Title changes to "TRASH"
- Shows deleted topics (latest version per group)
- Each item has permanent delete icon (trash can)
- "← Recent" button to return to Recent Topics

**Permanent Delete Flow:**
1. In Trash mode, hover over item → trash can icon appears
2. Click trash can → confirmation dialog
3. Dialog: "确认将此对话删除？删除此对话后将无法找回历史记录。"
4. Click "确认删除" → hard delete from database
5. Cannot be recovered

**Backend APIs:**
- `POST /api/history/group/{topic_group_id}/trash` - soft delete
- `DELETE /api/history/group/{topic_group_id}/permanent` - hard delete
- `POST /api/history/group/{topic_group_id}/restore` - restore from trash (backend ready, UI not implemented yet)

### 4. Date Filtering

**Feature:** Filter history by time range.

**UI:**
- Calendar icon in Recent Topics header
- Click → dropdown menu
- Options (all in English):
  - All
  - Past 1 hour
  - Past 3 hours
  - Today
  - Yesterday
  - Previous 7 Days
  - Previous 30 Days
- Selected option has checkmark
- Works with search (both filters apply)

**Backend:**
- `GET /api/history?date_filter=1h|3h|today|yesterday|7d|30d`
- Filters by `created_at` timestamp
- Uses UTC time for comparisons

### 5. Version Selector in Result Page

**Feature:** Switch between versions without re-generation.

**UI:**
- Appears below Output Info section
- Only visible when topic has multiple versions
- Dropdown showing "Version 1", "Version 2", "Version 3"
- Current version highlighted
- Click version → switches prompt content
- Output Slug and Output Directory update accordingly

**Backend:**
- `GET /api/history/group/{topic_group_id}/versions` - list all versions
- `GET /api/history/{history_id}` - load specific version

## Database Schema Changes

### New Fields (v0.3.2)

```sql
ALTER TABLE prompt_history ADD COLUMN deleted_at DATETIME;
ALTER TABLE prompt_history ADD COLUMN title_normalized TEXT;
ALTER TABLE prompt_history ADD COLUMN topic_group_id VARCHAR(100);
ALTER TABLE prompt_history ADD COLUMN version_number INTEGER NOT NULL DEFAULT 1;
```

### Migration Strategy

**Automatic Migration:**
- On first startup after upgrade, `init_db()` checks for missing columns
- Adds columns if not exist
- Backfills legacy data:
  - Each old record gets unique `topic_group_id` (format: `legacy_{uuid}`)
  - `version_number` set to 1
  - `title_normalized` computed from title
  - `deleted_at` remains NULL

**Migration is NON-DESTRUCTIVE:**
- No data loss
- No history deletion
- All old prompts remain accessible
- Can rollback by removing new columns (not recommended)

### Indexes

```sql
CREATE INDEX idx_topic_group_id ON prompt_history(topic_group_id);
```

## API Endpoints

### Enhanced Existing Endpoints

**GET /api/history**
- New query param: `date_filter` (optional)
- Returns only non-deleted records
- Returns only latest version per topic group
- Response includes `version_count` for each item

**GET /api/history/{history_id}**
- Can retrieve any version (including deleted)
- Response includes `version_count`

### New Endpoints (v0.3.2)

**GET /api/history/group/{topic_group_id}/versions**
- Lists all versions in a topic group
- Sorted by version_number ASC
- Returns: id, version_number, created_at, slug, deleted_at

**PATCH /api/history/group/{topic_group_id}/rename**
- Request body: `{"title": "new title"}`
- Updates all versions in group
- Returns latest version item

**POST /api/history/group/{topic_group_id}/trash**
- Soft delete all versions in group
- Sets `deleted_at` to current time
- Returns success status

**GET /api/trash**
- Lists deleted topics (latest version per group)
- Supports search query param `q`
- Sorted by deleted_at DESC

**DELETE /api/history/group/{topic_group_id}/permanent**
- Hard delete all versions in group
- Permanent, cannot be undone
- Returns success status

**POST /api/history/group/{topic_group_id}/restore** *(Backend only)*
- Restores topic from trash
- Sets `deleted_at` to NULL
- Frontend UI not implemented yet

## Performance Considerations

### Database Queries

**Optimized for version grouping:**
```sql
-- Gets only latest version per group
SELECT * FROM prompt_history p1
WHERE deleted_at IS NULL
AND (topic_group_id, version_number) IN (
    SELECT topic_group_id, MAX(version_number)
    FROM prompt_history
    WHERE deleted_at IS NULL
    GROUP BY topic_group_id
)
ORDER BY is_pinned DESC, created_at DESC
```

**Query performance:**
- Indexed on `topic_group_id`
- Subquery cached per request
- Typical response time: <50ms for 1000 records

### Frontend Performance

- Version list loaded only when viewing history item
- Version switch doesn't hit LLM API (reads from database)
- Rename uses debounced input (saves on blur/Enter only)
- Search uses 200ms debounce
- Date filter dropdown lightweight (no date picker library)

## Known Limitations

### Current Version (v0.3.2)

1. **No bulk operations:**
   - Cannot delete multiple topics at once
   - Cannot restore multiple items from trash

2. **No version comparison:**
   - Cannot see diff between Version 1 and Version 2
   - Cannot compare prompts side-by-side

3. **Trash has no restore UI:**
   - API endpoint exists: `POST /api/history/group/{topic_group_id}/restore`
   - Frontend button not implemented
   - Can restore via API call manually

4. **Date filter not available in Trash mode:**
   - Intentional simplification
   - Trash always shows all deleted items by `deleted_at DESC`

5. **No trash auto-cleanup:**
   - Deleted items stay in trash forever
   - No 30-day auto-purge
   - User must permanently delete manually

6. **Version grouping is title-based only:**
   - Cannot manually merge/split version groups
   - Cannot reassign version to different group
   - Normalization is simple (may not catch all variants)
