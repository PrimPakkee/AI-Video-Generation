# v0.6.3 — Static Image Video MVP + Generation Method Selector + Dark Mode Fix

## 概要

v0.6.3 在 Video Mode 主页同一个输入流程下新增第二条生成路线 **Image Video**（本地静态图合成视频 MVP），并保留原有的 v0.6.2 **Seedance Video** 链路；同时修复 dark mode 下大面积白框的渲染问题。

本版本明确**不**做的事：

- 不真实调用 APX
- 不调用 Seedance 真实接口
- 不调用 Image2
- 不调用 TTS

> 注意：Image Video 路线**会**调用 `AI_VIDEO_LLM_*`（默认 `gpt-5-chat`）来生成
> 每张幻灯片的英文文案 + 中文整体内容介绍。这个模型本来就是项目内 Prompt Mode
> 与 Seedance Content Asset Pipeline 共用的内容生成模型，**不**在禁止列表中。
> 当 `AI_VIDEO_LLM_API_KEY` 未配置或调用失败时，pipeline 会 fallback 到静态模板，
> 视频仍能生成，但文案会与题目细节不完全对齐——前端 Overview 会明确告知。
- 不做字幕 burn-in
- 不做 AI QA
- 不做批量生成
- 不修改 .env
- 不做强制 Preflight / Submit-to-Seedance 二次确认（旧设计已废弃）
- 不做 v0.6.4 / v0.6.5 / v0.7.0 内容
- 不 git add / 不 git commit / 不 git push

## 一、Generation Method Selector（首页）

`web/static/index.html` 在 Video duration selector 下方新增 `#video-method-selector`：

- `Seedance Video`（默认）— 走原有 v0.6.2 Seedance/APX 链路。
- `Image Video` — 走 v0.6.3 本地静态图合成 MVP。

`web/static/main.js` 新增 `getCurrentGenerationMethod()` 与按钮 wiring，并把 `generation_method` 加入 `/api/video/generate/start` 与 `/api/video/generate` 的请求 body。

兼容规则：

- 缺失或空字符串 → `seedance_video`（默认）。
- 非法值 → 后端返回 HTTP 400。

后端校验：`web/app.py::_normalize_generation_method` + `VideoGenerateRequest.generation_method`。

## 一·五、Slide 文案 + 中文 Overview 由 `AI_VIDEO_LLM_*` 生成

`web/image_video_pipeline.py::_call_llm_for_slide_content(...)` 在每次生成时调用
配置好的 OpenAI-compatible 模型（`AI_VIDEO_LLM_BASE_URL` + `AI_VIDEO_LLM_MODEL`，
默认 `gpt-5-chat`），让模型针对**当前题目**写出：

- `video_title_en`、`hook_question_en`、`answer_en`：整体英文 framing；
- `slides[*].title / caption / highlight / visual_focus / badge`：每张幻灯片
  的吸睛文案（标题 ≤ 7 词，caption ≤ 16 词），其中 `visual_focus` 描述
  Pillow 渲染器应突出的具体图形（例如 “a calendar with trial days marked”、
  “two coins side by side”）；
- `overview_cn`：4–7 句的中文连贯段落，专门写给前端 Overview tab，告诉用户
  这条视频在讲什么——题目 / 问题 / 关键洞察 / 答案 / 各部分画面，避免任何
  Pillow / FFmpeg / TTS 等技术词。

LLM 失败时自动 fallback 到 v0.6.3 初始版本的本地静态模板，pipeline 不会因此
崩溃或退化为「整体生成失败」。前端 Generation Evidence 会显示
`LLM Used: Yes/No`，Overview tab 也会标注「文案来源: LLM (gpt-5-chat)」或
「文案来源: 本地静态模板（LLM 未启用或失败）」。

API Key 永不入库、永不写入任何 outputs 文件、永不返回到前端，仅在
`outputs/<slug>/image_video/llm_debug.json` 里留下 `api_key_configured: bool`
+ 模型名 + base_url（不含 key）。

## 二、Image Video Pipeline（本地）

- `resolve_slide_count(duration_seconds, title=None)` — 严格按时长返回 slide 数。
- `generate_image_video_package(title, duration_seconds, output_dir, slug=None)` — 主入口。

输出布局（相对 `outputs/<slug>/`）：

## 三、Slide 数量规则（动态）

| Duration | Slide count |
| --- | --- |
| 5s  | exactly 3 |
| 15s | 4–6 |
| 30s | 6–8 |
| 60s | 10–15 |
| 90s | 20–25 |

`resolve_slide_count` 用 title 复杂度（词数、复杂关键词、标点、中文字符长度）在区间内取低/中/高值。同一 duration **不会**永远返回同一个值。

每张 slide 时长 = `duration_seconds / slide_count`（允许小数秒）。

非法 duration（5/15/30/60/90 之外）抛 `ValueError`，后端会 snap 到最近 bucket 或返回 400。

## 四、Slide Plan / Overlay Plan / 渲染

每张 slide 有 `role`，role 序列在 3..25 张范围内动态分配：

- 短序列（≤3）：hook / explanation / answer
- 中序列（≤6）：hook / setup / explanation / key_insight / answer / takeaway
- 长序列（>6）：上面 + misconception / comparison / example / recap

每个 role 对应一种本地 Pillow 布局：

- `hook` — 大问号 + 中央标题
- `setup` — 左右两个对比卡（A / B）
- `misconception` — 中央错误标记卡
- `explanation` — 三步连接箭头
- `comparison` — 两组柱状对比
- `example` — 数字示例卡
- `key_insight` — 中央高亮 insight 框
- `answer` — 答案 + 对勾
- `recap` — 三步迷你回顾
- `takeaway` — 总结卡 + Final Takeaway

所有文字由 Pillow 程序绘制，**不由图像模型生成**。Overlay 文本固定英文（中文题目自动 fallback 到 “This Topic” 或抽取 Latin 部分）。

## 五、FFmpeg 合成

- 使用 `shutil.which("ffmpeg")` 探测；缺失时 `route_status="failed"` + 明确错误 `"FFmpeg is required for Image Video composition. Please install ffmpeg."`，**不崩溃**。
- 命令行使用 concat demuxer：H.264 / yuv420p / 16:9 / 1920×1080 / fps 24。
- 当前版本无音频（`has_audio=false`，`tts_status=not_implemented_v0.6.3`）。
- 持久化 `concat.txt` 与 `ffmpeg_command.txt` 便于排查。

## 六、后端接入

`web/app.py`：

- `VideoGenerateRequest.generation_method` 字段。
- `_normalize_generation_method` 校验 / 缺省。
- `_run_image_video_pipeline` 在写好 VideoHistory 之后调用本地 pipeline，并通过 `VideoHistoryRepository.update_image_video_result` 把 `video_file_path`（相对 `outputs/`）+ duration + status + metadata 写回数据库。
- `/api/video/generate` 与 `/api/video/generate/start` 都按 `generation_method` 分发。
- Image Video 路线**绝不**调用 `ApxSeedanceProvider` / `seedance_prompt_compiler` / `build_video_content_assets` / Image2 / TTS。
- 失败时返回 HTTP 200 + `success=false` + `error` 字段，前端可显示。

`/api/video/history/{id}/asset/video` 复用现有 `_resolve_safe_outputs_path`，对两种 method 都适用。

## 七、数据库迁移

`VideoHistory.generation_method`：

- 类型 `String(40)`，默认 `'seedance_video'`。
- `web/db/video_database.py::init_video_db` 启动时执行 idempotent 的 `ALTER TABLE video_history ADD COLUMN generation_method ...`。
- `to_dict()` 返回 `generation_method`。
- 老记录默认 `'seedance_video'`，旧链路行为不变。
