# AI Video Generation - 产品需求文档（PRD）

## 一、项目背景

### 1.1 业务背景
Think Academy 海外业务正在探索 AI 教育短视频作为内容营销和品牌传播的新渠道。短视频平台（TikTok、YouTube Shorts、Instagram Reels、小红书）是触达海外学生和家长的高效方式。

我们的内容形式是：**趣味题目 + 可视化推理 + 清晰讲解 + 答案揭晓**，既有教育价值，又有传播潜力。

### 1.2 当前痛点
目前的视频生产流程过度依赖人工，效率低、标准不一致：

**现状流程**：
1. 人工从选题库选题
2. 人工在 ChatGPT 中生成适合 NotebookLM 的 Prompt
3. 人工复制 Prompt 到 NotebookLM，等待生成
4. （可选）在 Gamma 生成静态图，再用即梦 AI 让图片动起来
5. 人工让 ChatGPT 生成口播文案
6. 人工在剪映中合成视频、口播、字幕
7. 人工导出、上传

**痛点总结**：
- ⏱️ **效率低**：一条视频从选题到成片需要 2-4 小时
- 🔀 **流程分散**：需要在 5-6 个工具之间切换
- 📋 **标准不一致**：每次生成的风格、结构、质量都不稳定
- 🔄 **难以复用**：没有标准化模板，每次都从头开始
- ❌ **质量不可控**：有时生成双人对话、黑色背景、错误答案

## 二、产品目标

### 2.1 核心目标
构建一个 **AI Educational Video Workflow Engine（AI 教育短视频工作流引擎）**，从选题到成片实现端到端自动化。

**最终愿景**：输入一个选题 → 输出一个可发布的 mp4 短视频。

**当前阶段**：建立标准化的文档和模板体系，为后续自动化打下基础。

### 2.2 目标用户
- **主要用户**：Think Academy 内容运营团队（视频编导、内容策划）
- **次要用户**：产品经理、海外市场团队
- **未来用户**：任何需要批量生产教育短视频的团队

### 2.3 使用场景

#### 场景 1：批量生产教育短视频资料
**触发**：运营团队需要在一周内产出 20 条教育短视频  
**需求**：快速从选题库生成标准化的视频生产资料  
**期望**：每条视频的生产资料生成时间从 30 分钟降低到 5 分钟

#### 场景 2：保证视频风格一致性
**触发**：多个内容创作者同时生产视频，风格不统一  
**需求**：统一的风格指南和质量检查清单  
**期望**：所有视频都符合 Think Academy AI 品牌风格（单人旁白、白底线稿、教育风格）

#### 场景 3：新人快速上手
**触发**：新加入的内容实习生需要快速学习视频生产规范  
**需求**：清晰的文档和可复用的模板  
**期望**：新人在 1 天内理解流程，3 天内独立产出合格的视频资料

## 三、产品方案

### 3.1 核心流程设计

```
输入：选题（例如："连续5次正面后，下一次更可能反面吗"）
↓
处理：填充标准化模板
↓
输出：完整的视频生产资料（15 个标准字段）
↓
使用：人工复制到 NotebookLM / 剪映，完成视频制作
```

### 3.2 标准化输出（15 个字段）

每条视频必须输出以下结构化资料：

1. **题目重写与英文标题** - 优化传播效果
2. **核心概念** - 例如：Gambler's Fallacy（赌徒谬误）
3. **视频定位** - 平台、受众、时长、难度
4. **开头钩子** - 前 3 秒吸引注意力的问题
5. **完整题面** - 清晰陈述问题
6. **正确答案** - 必须逻辑正确
7. **详细推理过程** - 分步骤讲解
8. **单人旁白口播稿** - 适合 single narrator
9. **屏幕字幕建议** - 大而清晰的关键文字
10. **画面分镜 / storyboard** - 每个镜头的画面描述
11. **NotebookLM 可直接复制的完整 Prompt** - 一键复制
12. **视觉风格限制** - 白底线稿、简洁图示
13. **禁止事项** - 不要双人对话、黑色背景等
14. **质量检查清单** - 上线前必查项
15. **输出文件路径** - 保存到 `outputs/` 文件夹

### 3.3 版本路线与 MVP 范围

#### V0 - 文档和模板体系（当前版本，已完成）
**目标**：建立标准化的视频生产规范和模板

**包含内容**：
- 📋 完整的产品文档（PRD、工作流、风格指南、Schema、技术路线）
- 📝 可复用的模板库（NotebookLM Prompt、分镜、QA）
- 📊 示例选题库（JSONL 格式，可扩展）
- 🎯 标准化的输出结构设计

**不包含内容**：
- ❌ 不自动生成脚本（需人工填充模板）
- ❌ 不调用任何 API
- ❌ 不自动合成视频

**成功标准**：
- ✅ 团队成员能够使用模板独立产出视频资料
- ✅ 每条视频资料生成时间 < 30 分钟
- ✅ 风格一致性 > 80%

---

#### V1 - 自动生成 Video Package（1-2 个月）
**目标**：输入题目，自动生成完整的视频生产资料

**核心功能**：
- ✅ CLI 工具：`python scripts/generate_video_package.py --topic "题目"`
- ✅ 调用 ChatGPT API 生成脚本、分镜、旁白
- ✅ 自动填充 NotebookLM Prompt 模板
- ✅ 自动保存到 `outputs/` 文件夹（Markdown / JSON 格式）
- ✅ 自动运行质量检查

**技术栈**：
- Python 3.10+
- OpenAI API (GPT-4)
- Jinja2 模板引擎

**成功标准**：
- ✅ 每条视频资料生成时间从 30 分钟降低到 5 分钟
- ✅ 自动生成的脚本质量 > 80 分（人工评分）
- ✅ 批量生成 20 条视频资料的时间 < 2 小时

---

#### V2 - 结构化输出与批量处理（2-3 个月）
**目标**：批量处理选题库，结构化输出

**核心功能**：
- ✅ 批量处理模式：`python scripts/run_pipeline.py --batch`
- ✅ 结构化输出（JSON / YAML 格式），便于后续工具读取
- ✅ 自动质量检查和评分
- ✅ 生成两种输出：
  - NotebookLM Prompt（用于 NotebookLM 生成视频）
  - 独立脚本（用于 Direct Video Pipeline）

**技术栈**：
- 多线程处理
- 数据库存储（SQLite）
- 自动化测试

**成功标准**：
- ✅ 批量生成 100 条视频资料的时间 < 10 小时
- ✅ 自动质量检查通过率 > 90%
- ✅ 结构化输出格式稳定，可被后续工具读取

---

#### V3 - 半自动视频生成（3-6 个月）
**目标**：接入 TTS、图片生成、视频生成 API，实现半自动视频合成

**核心功能**：
- ✅ TTS 音频生成：调用 ElevenLabs / Azure TTS / OpenAI TTS
- ✅ 图片生成：调用 DALL-E / Midjourney / Stable Diffusion
- ✅ 视频生成：调用 Runway / Pika / Luma AI
- ✅ 字幕生成：根据旁白自动生成 SRT 文件
- ✅ ffmpeg 自动合成：音频 + 画面 + 字幕 → mp4 视频
- ✅ 初版视频质量评分

**技术栈**：
- ffmpeg
- ElevenLabs API / Azure TTS
- Stable Diffusion / DALL-E API
- Runway API / Pika API

**成功标准**：
- ✅ 自动生成的视频质量 > 70 分（人工评分）
- ✅ 视频生成时间 < 10 分钟/条
- ✅ 字幕准确率 > 95%

---

#### V4 - 端到端自动化（6-12 个月）
**目标**：输入题目，直接输出可发布的 mp4 视频

**核心功能**：
- 🎯 一键生成：`python scripts/run_pipeline.py --topic "题目" --output-video`
- 🎯 自动质量评分（内容准确性、视觉风格、传播潜力）
- 🎯 根据视频表现数据（播放量、完播率、点赞率）优化 Prompt
- 🎯 A/B 测试不同风格（例如：更活泼 vs 更严肃）
- 🎯 自动上传到短视频平台（TikTok / YouTube Shorts）

**技术栈**：
- 机器学习模型（质量评分）
- 数据分析（视频表现追踪）
- 平台 API（TikTok / YouTube）

**成功标准**：
- 🎯 视频生成时间 < 5 分钟/条
- 🎯 自动生成的视频质量 > 85 分
- 🎯 无需人工介入即可发布
- 🎯 视频表现（播放量、完播率）与人工制作视频持平或更好

## 四、产品设计细节

### 4.1 选题库结构
文件：`data/topic_library_sample.jsonl`

**关于 JSONL 格式**：
- JSONL（JSON Lines）格式，每一行是一个完整的 JSON object
- 每一行代表一个视频选题
- 比 CSV 更稳定，适合包含逗号、中文、英文、长文本的字段
- 不会出现 CSV 常见的字段错位问题
- Python 脚本可以逐行读取，内存占用低

| 字段 | 说明 | 示例 |
|------|------|------|
| id | 唯一标识 | 001 |
| category | 分类 | 概率论 / 视觉错觉 / 逻辑推理 |
| title_cn | 中文标题 | 连续5次正面后,下一次更可能反面吗 |
| title_en | 英文标题 | The Coin Toss Trap |
| core_concept | 核心概念 | Gambler's Fallacy |
| target_duration | 目标时长 | 45s / 60s / 90s |
| difficulty | 难度 | easy / medium / hard |
| visual_feasibility | 可视化难度 | high / medium / low |
| viral_potential | 传播潜力 | high / medium / low |
| status | 状态 | pending / in_production / completed |

### 4.2 模板设计

#### 模板 1：NotebookLM Prompt Template
**文件**：`templates/notebooklm_prompt_template.md`  
**用途**：填充题目信息后，直接复制到 NotebookLM

**核心结构**：
```
[Topic] - 题目
[Core Concept] - 核心概念
[Target Audience] - 受众
[Video Duration] - 时长
[Hook] - 开头钩子
[Problem Statement] - 题面
[Correct Answer] - 答案
[Reasoning Process] - 推理过程
[Narration Script] - 旁白
[Visual Style] - 视觉风格
[Restrictions] - 禁止事项
```

#### 模板 2：Storyboard Template
**文件**：`templates/storyboard_template.md`  
**用途**：设计每个镜头的画面和文字

**核心结构**：
```
Scene 1 (0-3s): [画面描述] + [字幕]
Scene 2 (3-10s): [画面描述] + [字幕]
...
```

#### 模板 3：QA Checklist Template
**文件**：`templates/qa_checklist_template.md`  
**用途**：视频上线前的质量检查

**核心检查项**：
- [ ] 答案逻辑正确
- [ ] 单人旁白（非双人对话）
- [ ] 白底线稿风格
- [ ] 字幕大而清晰
- [ ] 核心图示前后一致
- [ ] 无黑色背景、恐怖元素
- [ ] 画面与推理对应

### 4.3 风格规范
详见 `docs/style_guide.md`

**核心原则**：
- ⭐ Single narrator（单人旁白）
- ⭐ White background（白底）
- ⭐ Clean line art（简洁线稿）
- ⭐ Large captions（大字幕）
- ⭐ Consistent core diagrams（一致图示）

**禁止事项**：
- ❌ 双人对话、访谈、播客
- ❌ 黑色背景、恐怖风格
- ❌ 复杂背景、无关装饰

## 六、风险与依赖

### 6.1 技术依赖
- **NotebookLM**：目前没有公开 API，需人工复制 Prompt
- **ChatGPT API**：V2 阶段需要 API 访问权限
- **剪映**：目前没有 API，需人工操作

### 6.2 内容风险
- **答案正确性**：必须确保推理逻辑正确，不能为了传播牺牲准确性
- **风格一致性**：需要持续监控和优化 Prompt，避免风格漂移

### 6.3 资源需求
- **人力**：产品实习生 1 人（当前），内容运营 2-3 人（使用者）
- **工具成本**：ChatGPT API（V2）、NotebookLM（免费但需等待 API）、剪映（免费）

## 七、两种工作模式

### 模式 A：NotebookLM Prompt Mode
```
输入题目 
→ 生成 NotebookLM Prompt（V0 人工填充，V1+ 自动生成）
→ 人工复制到 NotebookLM 
→ NotebookLM 生成视频 
→ 在剪映中后期调整 
→ 输出 mp4 视频
```

**优点**：
- 利用 NotebookLM 的视频生成能力
- 视频质量较高（NotebookLM 已优化）

**缺点**：
- 需要人工复制粘贴
- 依赖 NotebookLM（没有公开 API）
- 批量生产效率低

**适用阶段**：V0、V1、V2

---

### 模式 B：Direct Video Pipeline Mode
```
输入题目 
→ 自动生成脚本、分镜 
→ 自动生成画面提示词 
→ 调用图片/视频生成 API 
→ 调用 TTS 生成旁白音频 
→ 自动生成字幕文件 
→ ffmpeg 自动合成 
→ 输出 mp4 视频
```

**优点**：
- 完全自动化，无需人工介入
- 批量生产效率高
- 不依赖外部工具

**缺点**：
- 初期视频质量可能不如 NotebookLM
- 需要接入多个 API（成本较高）
- 技术复杂度高

**适用阶段**：V3、V4

---

### 混合模式（推荐）
在 V3、V4 阶段，可以同时支持两种模式：
- 对于重点视频，使用 NotebookLM Mode，人工检查质量
- 对于批量视频，使用 Direct Video Pipeline Mode，自动生产
