# v0.4.7 Prompt模式稳定性修复与数据保护

**版本号**: v0.4.7  
**更新日期**: 2026-05-27  
**更新类型**: 稳定性修复 / 数据保护 / 测试体系补充  
**父版本**: v0.4.6.9

## 问题背景

在 v0.4.6.9 完成严格评分校准后,系统已经具备完整的功能:数据库、版本管理、AI Review、编辑功能等。但在实际使用中发现了严重的**数据稳定性问题**:

### 症状1:编辑状态混乱

- 进入历史题目后,点击 AI Review,再点击 Edit,会弹出保存失败
- 点确定后,再切回 Raw Text,原本有内容的 Raw Text 可能直接变成空白
- 某些历史记录的 Preview 突然变成空白

**示例**:
用户点击 AI Review tab → 点击 Edit 图标 → 进入空白 textarea → 点击 Save → 保存失败 → Raw Text 变空

### 症状2:数据库出现损坏数据

检查数据库发现:
- id=3: prompt_text 只有 9 个字符
- id=13: prompt_text 完全为空
- id=14: preview_text 为空

**数据审计结果**:
```
[HIGH] id=3 title=为什么免费试用最危险 issues=prompt_text_too_short(9)
[HIGH] id=13 title=为什么只看成功案例会被骗 issues=prompt_text_empty
[MEDIUM] id=14 title=为什么地图可能只需要四种颜色 issues=preview_text_empty
```

### 症状3:状态切换混乱

- 点击不同 tab(Raw / Preview / Overview / AI Review)
- 点击编辑、点击保存
- 切换历史题目
- 编辑中切换 tab

这些操作之间存在状态混乱,导致:
- Raw Text 变空
- Preview 丢失
- 保存失败后页面状态错误

### 症状4:缺少测试体系

- 没有完整的黑盒/白盒测试清单
- 每次改一个功能都可能引入新的隐藏 bug
- 数据损坏后没有恢复脚本
- 没有稳定性检查脚本

## 根本原因分析

### 原因1:Edit 允许在 AI Review 模式下触发

**代码问题**:
```javascript
// main.js - enterEditMode()
function enterEditMode() {
    if (isEditingPrompt) {
        return;
    }

    isEditingPrompt = true;

    // 问题:没有检查 currentPromptViewMode
    // 允许在 review 模式下进入编辑
    let contentToEdit = '';
    if (currentPromptViewMode === 'raw') {
        contentToEdit = currentRawText;
    } else if (currentPromptViewMode === 'preview') {
        ...
    } else if (currentPromptViewMode === 'overview') {
        ...
    }
    // 如果 currentPromptViewMode === 'review',contentToEdit 为空字符串
}
```

**问题分析**:
- AI Review 是生成的质检报告,不应该被手动编辑
- 但 enterEditMode() 没有阻止 review 模式
- 如果用户在 AI Review tab 点击 Edit,contentToEdit 为空
- 保存空字符串会清空数据库

---

### 原因2:编辑状态下允许切换 tab

**代码问题**:
```javascript
// main.js - switchPromptViewMode()
function switchPromptViewMode(mode) {
    // 问题:没有检查 isEditingPrompt 状态
    currentPromptViewMode = mode;

    // 直接切换 tab,导致编辑状态混乱
    if (mode === 'raw') {
        rawEl.classList.remove('hidden');
        ...
    }
}
```

**问题分析**:
- 用户在 Raw Text 编辑中
- 点击 Preview 或 AI Review
- textarea 内容还在,但 tab 切换了
- 用户看到的是 Preview,但 isEditingPrompt = true
- 保存时不知道保存的是哪个 view

---

### 原因3:保存失败后状态没有正确恢复

**代码问题**:
```javascript
// main.js - exitEditMode()
async function exitEditMode() {
    ...

    if (data.success) {
        // 更新本地状态
        ...
    } else {
        alert('Failed to save: ' + (data.error || 'Unknown error'));
        return; // ← 直接 return,但 isEditingPrompt 仍然可能是 true
    }

    // 问题:如果保存失败,这段代码不会执行
    isEditingPrompt = false;
    // 恢复 read-only
    promptContent.setAttribute('readonly', 'readonly');
    ...
}
```

**问题分析**:
- 保存失败后直接 return
- 但没有恢复 isEditingPrompt = false
- 用户看到错误提示,但编辑状态可能已经错乱
- 再次尝试保存可能触发更多问题

---

### 原因4:前端允许空内容写入

**代码问题**:
```javascript
// main.js - exitEditMode()
async function exitEditMode() {
    const editedContent = promptContent.value;

    // 问题:没有校验 editedContent 是否为空
    const response = await fetch(`/api/history/${currentHistoryId}`, {
        method: 'PATCH',
        body: JSON.stringify({
            view: view,
            content: editedContent // ← 可能是空字符串
        }),
    });
}
```

**问题分析**:
- 如果用户全选删除内容
- editedContent = ""
- 前端没有阻止,直接发送 PATCH
- 后端也没有阻止,写入数据库
- prompt_text 被清空

---

### 原因5:后端没有 raw prompt 数据保护

**代码问题**:
```python
# web/app.py - UpdateContentRequest
class UpdateContentRequest(BaseModel):
    view: str = Field(..., pattern='^(raw|preview|overview)$')
    content: str = Field(..., min_length=0)  # ← 允许 min_length=0
```

```python
# web/app.py - PATCH /api/history/{history_id}
@app.patch("/api/history/{history_id}")
async def update_history_content(...):
    # 问题:没有检查 content 是否为空或过短
    record = PromptHistoryRepository.update_prompt_content(
        db, history_id, request.view, request.content
    )
```

**问题分析**:
- FastAPI 层允许 content 最小长度为 0
- PATCH 接口没有检查 view == 'raw' 时 content 不能为空
- 直接写入数据库,导致 prompt_text 为空

---

### 原因6:数据库缺少恢复脚本

**问题**:
- 数据库出现损坏数据后,没有自动检测脚本
- 没有从 outputs 文件恢复的脚本
- 只能手动修复,效率低,容易遗漏

---

### 原因7:缺少系统性黑盒/白盒回归测试

**问题**:
- 每次修改功能后,只测试新功能
- 没有测试是否影响旧功能
- 没有固定的测试清单
- 导致引入 bug 后很晚才发现

## 设计目标

**暂停新功能开发,专注稳定性修复**:

### 核心原则

✅ **数据不丢**:任何操作都不允许清空或破坏 prompt_text  
✅ **页面不乱**:编辑状态切换必须清晰、可控  
✅ **编辑不误保存**:空内容、异常短内容必须阻止保存  
✅ **历史记录可恢复**:数据库损坏后可以从 outputs 恢复  
✅ **核心流程可稳定使用**:编辑、保存、切换、查看必须稳定

### 修复4:保存失败不再破坏页面状态

**文件**: `web/static/main.js`

**修改**: `exitEditMode()` 函数错误处理

**核心逻辑**:
```javascript
async function exitEditMode() {
    ...

    try {
        const response = await fetch(`/api/history/${currentHistoryId}`, {
            method: 'PATCH',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({
                view: view,
                content: editedContent
            }),
        });

        if (!response.ok) {
            // Try to parse error from backend
            let errorMsg = 'Unknown error';
            try {
                const errorData = await response.json();
                errorMsg = errorData.detail || errorData.error || errorMsg;
            } catch (e) {
                errorMsg = `HTTP ${response.status}: ${response.statusText}`;
            }

            alert(`Failed to save: ${errorMsg}\n\nYour changes are still in the editor. Please fix the issue or copy your content before closing.`);
            return; // Stay in editing mode, preserve textarea content
        }

        const data = await response.json();

        if (data.success) {
            // Update local state only after successful save
            ...
        } else {
            const errorMsg = data.error || data.detail || 'Unknown error';
            alert(`Failed to save: ${errorMsg}\n\nYour changes are still in the editor.`);
            return; // Stay in editing mode
        }
    } catch (error) {
        console.error('Save error:', error);
        alert(`Failed to save: ${error.message}\n\nYour changes are still in the editor. Please try again or copy your content.`);
        return; // Stay in editing mode, preserve textarea content
    }

    // Exit editing mode only after successful save
    isEditingPrompt = false;
    ...
```

### 修复5:后端拒绝空 prompt 和异常短 prompt

**文件**: `web/app.py`

**修改**: `PATCH /api/history/{history_id}` 接口

**核心逻辑**:
```python
@app.patch("/api/history/{history_id}")
async def update_history_content(...):
    try:
        # CRITICAL DATA PROTECTION: Validate view and content before saving
        view = request.view
        content = request.content

        # Check 1: View must be one of the allowed values
        if view not in ['raw', 'preview', 'overview']:
            return JSONResponse(
                status_code=400,
                content={
                    "success": False,
                    "error": f"Invalid view: {view}. Only raw, preview, or overview can be edited."
                }
            )

        # Check 2: For raw text, content cannot be empty or too short
        if view == 'raw':
            trimmed_content = content.strip()

            # Empty check
            if not trimmed_content:
                return JSONResponse(
                    status_code=400,
                    content={
                        "success": False,
                        "error": "Raw Text cannot be empty. Save rejected to prevent data loss."
                    }
                )

            # Length check
            if len(trimmed_content) < 500:
                return JSONResponse(
                    status_code=400,
                    content={
                        "success": False,
                        "error": f"Raw Text is too short ({len(trimmed_content)} characters). Save rejected to prevent data loss."
                    }
                )

        # Proceed with save
        record = PromptHistoryRepository.update_prompt_content(...)

        # Mark AI Review as stale only when raw text is edited
        if view == 'raw':
            ...

        return {
            "success": True,
            ...
        }
    except Exception as e:
        return JSONResponse(
            status_code=500,
            content={
                "success": False,
                "error": str(e)
            }
        )
```

**改进**:
- ✅ view 必须是 raw / preview / overview
- ✅ raw text 不能为空
- ✅ raw text 长度 <500 时拒绝保存
- ✅ 返回 400 和详细错误信息
- ✅ 双重保护:前端 + 后端

## 已知限制

1. **编辑中切换必须先保存**
   - 编辑状态下无法快速切换 tab
   - 必须先保存或取消编辑
   - 未来可考虑自动保存或提示保存/放弃对话框

2. **Raw Text 长度硬性限制 500 字符**
   - 如果用户确实需要保存短 prompt,需要点击"OK"确认
   - 大部分 NotebookLM prompt 都 >500 字符,这个限制合理

3. **Preview / Overview 编辑可以为空**
   - Preview 和 Overview 允许较短或为空
   - 因为这两个是辅助内容,不是核心 prompt
