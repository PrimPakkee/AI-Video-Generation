## 问题背景

在 v0.4.6.3 发布后，用户在使用 AI Review 功能时遇到以下问题：

### 症状 1：大量题目生成失败

- 用户点击 "AI Review" 按钮
- 页面显示加载动画
- 几秒后显示：**"AI Review generation failed. Please try again."**
- 没有任何具体错误信息
- **影响范围**: 大量历史题目无法生成 AI Review

### 症状 2：Try Again 按钮无效

- 用户点击失败提示中的 "Try Again" 按钮
- 页面仍然显示相同的失败提示
- **没有真正重新调用 LLM 生成**
- 用户反复点击无效，功能完全不可用

### 症状 3：错误信息不透明

- 页面只显示通用错误提示
- 后端终端没有打印真实错误
- 数据库中没有保存详细错误信息
- **无法诊断为什么生成失败**
- 开发者无法定位问题根源

## 根本原因分析

### 原因 1：Try Again 按钮逻辑错误

**位置**: `web/static/ai_review.js:loadReview(force=true)`

**问题代码**:
```javascript
async function loadReview(force = false) {
    // Step 1: GET review status
    const getResponse = await fetch(`/api/history/${historyId}/review`);
    const getData = await getResponse.json();
    
    // 问题：即使 force=true，仍然先 GET
    if (status === 'failed') {
        // 直接 return，不执行后续 POST
        reviewEl.innerHTML = `<div class="review-error">...</div>`;
        return;  // ← BUG: 在这里就返回了，不会执行 POST
    }
    
    // 这段代码永远不会执行（因为上面已经 return）
    const postResponse = await fetch(`/api/history/${historyId}/review?force=true`, {
        method: 'POST'
    });
}
```

**问题分析**:
- `loadReview(true)` 仍然先执行 GET 请求
- GET 返回 `status='failed'`（因为上次生成失败）
- 代码在第 83-94 行直接 `return`，展示失败 UI
- **POST 请求根本没有执行**
- 即使传入 `force=true`，也被旧的 failed 状态拦截

**时间线**:
1. T=0s: 首次生成失败，status='failed'
2. T=10s: 用户点击 "Try Again"
3. T=10s: 调用 `loadReview(true)`
4. T=10s: GET 返回 status='failed'
5. T=10s: 代码直接 return，显示失败 UI
6. **POST ?force=true 从未执行**

### 原因 2：错误信息被隐藏

**位置**: `web/app.py:generate_review()`

**问题代码**:
```python
except Exception as llm_error:
    PromptReviewRepository.mark_review_failed(
        db=db,
        history_id=history_id,
        error_message=str(llm_error)  # ← 保存了错误，但...
    )
    
    # ← 没有打印到终端
    
    return JSONResponse(
        status_code=500,
        content={
            "success": False,
            "error": "AI Review generation failed. Please try again."
            # ← 只返回通用错误，没有 debug_error 字段
        }
    )
```

**问题分析**:
- 真实错误信息被保存到数据库（`error_message=str(llm_error)`）
- 但**没有打印到终端**，开发者看不到
- 返回给前端的只有通用错误提示
- **没有 debug_error 字段**供 console.error 输出
- 排查问题时完全没有线索

**影响**:
- 无法知道是 JSON 解析失败、API 超时、还是格式错误
- 无法定位是哪个题目、哪个字段出问题
- 无法针对性修复

### 原因 3：JSON 解析容错不足

**位置**: `scripts/llm_topic_enhancer.py:review_prompt()`

**问题**:
- LLM 返回的 JSON 可能有轻微格式问题
- 例如：`"score": "14"` (字符串而非数字)
- 例如：缺少 `llm_score` 字段
- 例如：`total_score` 缺失或不是整数
- **当前代码直接抛出异常，导致整个 AI Review 失败**

**常见 LLM 输出问题**:
1. 返回 `"score": "14"` 而非 `"score": 14`
2. 返回 `"total_score": "89"` 而非 `"total_score": 89`
3. 缺少 `llm_score` 字段（需要自动补成 "14/15"）
4. 缺少 `llm_comment` 字段
5. 缺少 `overall_review` 字段
6. `total_score` 与 `rows.score` 之和不一致
7. 返回的 `rows` 数量不是 8
8. 返回了 markdown code fence: ` ```json ... ``` `

**影响**:
- 即使 LLM 返回的内容实际可用，也会因为格式问题失败
- 增加失败率，降低功能可用性

### 原因 4：错误日志不详细

**问题**:
- `parse_json_response` 失败时，只打印前 200 字符
- 对于长响应（AI Review 通常 2000+ 字符），看不到尾部内容
- 无法判断是否被截断、是否缺少结束括号

## 修复内容

### 修复 1：Try Again 真正重新生成

**文件**: `web/static/ai_review.js`

**修复逻辑**:
```javascript
async function loadReview(force = false) {
    const historyId = currentHistoryId;
    const reviewEl = document.getElementById('prompt-review');
    const key = `review_${historyId}`;

    // 关键修复：如果 force=true，跳过 GET 检查，直接 POST
    if (force) {
        reviewEl.innerHTML = `
            <div class="review-loading">
                <div class="spinner"></div>
                <p>Regenerating AI Review...</p>
                <p style="font-size: 12px;">This may take 20-30 seconds</p>
            </div>
        `;

        // 直接 POST ?force=true，不被 failed 状态拦截
        const postResponse = await fetch(`/api/history/${historyId}/review?force=true`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' }
        });

        const postData = await postResponse.json();

        // 打印 debug 错误到 console
        if (postData.debug_error) {
            console.error('[AI Review Debug Error]', postData.debug_error);
        }

        // 处理生成结果
        if (postData.status === 'generating') {
            startReviewPolling(historyId);
        } else if (postData.success && postData.review) {
            currentReviewData = postData.review;
            renderReview(currentReviewData);
        } else {
            // 显示失败 UI
            reviewEl.innerHTML = `<div class="review-error">...</div>`;
        }
        return;
    }

    // 非 force 模式：正常 GET-first 逻辑
    // ...
}
```

**关键改进**:
- ✅ `force=true` 时直接跳过 GET 检查
- ✅ 直接执行 POST `?force=true`
- ✅ 不会被旧的 `status='failed'` 拦截
- ✅ 打印 `debug_error` 到 console

**用户体验**:
- 点击 "Try Again" → 真正重新调用 LLM
- 页面显示 "Regenerating AI Review..."
- 如果成功，立即展示新结果
- 如果失败，console 有详细错误信息

### 修复 3：增强 JSON 解析容错

**文件**: `scripts/llm_topic_enhancer.py`

**新增方法**: `_normalize_review_data(review_data)`

**容错功能**:
```python
def _normalize_review_data(self, review_data):
    """修复 AI Review JSON 常见格式问题"""
    
    # 1. 转换字符串 score 为整数
    if isinstance(row["score"], str):
        row["score"] = int(row["score"])
    
    # 2. 自动补充 llm_score
    if "llm_score" not in row:
        row["llm_score"] = f"{row['score']}/{row['max_score']}"
    
    # 3. 自动补充 llm_comment
    if "llm_comment" not in row:
        row["llm_comment"] = "No detailed comment provided."
    
    # 4. 转换字符串 total_score 为整数
    if isinstance(review_data["total_score"], str):
        review_data["total_score"] = int(review_data["total_score"])
    
    # 5. 自动计算 total_score（如果缺失）
    if "total_score" not in review_data:
        total = sum(row["score"] for row in review_data["rows"])
        review_data["total_score"] = total
    
    # 6. 自动生成 overall_review（如果缺失）
    if "overall_review" not in review_data:
        score = review_data["total_score"]
        review_data["overall_review"] = f"Prompt scored {score}/100. ..."
    
    return review_data
```

**调用位置**:
```python
def review_prompt(self, raw_prompt, dry_run=False):
    # ...
    response_text = self.call_chat_messages_api(...)
    review_data = self.parse_json_response(response_text)
    
    # 关键：在 validation 之前先规范化
    review_data = self._normalize_review_data(review_data)
    
    # 再进行 validation
    if "rows" not in review_data:
        raise ValueError("...")
```

**关键改进**:
- ✅ 处理字符串数字 (`"14"` → `14`)
- ✅ 自动补充缺失字段 (`llm_score`, `llm_comment`)
- ✅ 自动计算 `total_score`
- ✅ 自动生成 `overall_review`
- ✅ 轻微格式问题不再导致失败

## 保持现有功能不变

本次修复**不影响**以下现有功能：

### 缓存逻辑保持不变

✅ **同一 history/version/schema 已 completed → 直接读取数据库**
- 切换 Raw Text / Preview / Overview / AI Review 不重新生成
- 切换其他题目再回来不重新生成

✅ **Edit 保存 → 当前 version 的 AI Review 变为 stale**
- 下次点击 AI Review 会重新生成

✅ **Regenerate → 新 version 独立生成 AI Review**
- 旧 version 的 AI Review 保留

✅ **Try Again → 用户主动重试**
- 允许重新生成 failed review
- 通过 `force=true` 实现

### Polling 逻辑保持不变

✅ **固定 historyId 轮询**
- 用户切换题目不影响轮询
- 轮询使用固定 historyId，不使用全局变量

✅ **Generating 超时检测（5 分钟）**
- 超时自动标记为 failed

## 已知限制

1. **JSON 容错不能解决所有问题**
   - 如果 LLM 返回完全无效的 JSON，仍会失败
   - 如果 `rows` 数量不是 8，仍会失败（这是合理的）
   - 容错只处理轻微格式问题

2. **前端只打印 debug_error 到 console**
   - 页面仍只显示简洁错误提示
   - 普通用户看不到详细错误
   - 开发者需要打开 console 查看

3. **不会自动重试失败的 review**
   - 需要用户手动点击 "Try Again"
   - 未来可考虑自动重试机制（不在本次修复范围）

## 未来改进方向

1. **自动重试机制**
   - LLM 调用失败时自动重试 1-2 次
   - 减少用户手动 "Try Again" 的次数

2. **更智能的 JSON 修复**
   - 使用正则表达式修复常见格式问题
   - 自动补全缺失的括号、逗号

3. **分段生成**
   - 将 8 个维度分成 2-3 次 API 调用
   - 降低单次调用失败的影响

4. **Review 质量监控**
   - 统计各题目的 review 成功率
   - 识别哪些类型的 prompt 容易失败
